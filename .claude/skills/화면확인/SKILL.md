# 화면확인 스킬

코드만 고치고 끝내지 않는다. UI에 영향을 주는 수정을 했으면 **그 결과를 실제로 렌더링해서 이미지로 보여주는 것까지가 작업의 끝**이다.

## 언제 실행하나

- `public/*.html`, `public/style.css`, `public/host.js`, `public/player.js` 등 화면에 보이는 결과물을 바꾸는 수정을 했을 때 — 사용자가 "보여줘"라고 말하지 않아도 매번.
- 여러 화면을 연달아 고쳤으면 화면마다 한 번씩.
- 순수 서버 로직(server/src/**)만 고치고 화면에 아무 영향이 없으면 스킵해도 된다.

## 절차

1. **개발 서버 확인** — `curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/host`로 이미 떠 있는지 먼저 확인한다. 이미 200이면 그대로 쓴다(정적 파일 수정은 서버 재시작이 필요 없다). 안 떠 있으면 `npm run dev`로 새로 띄운다. 포트 충돌(EADDRINUSE)이 나면 기존 프로세스를 무작정 죽이지 말고, 먼저 그게 사용자가 진행 중인 실제 테스트 세션(예: 여러 플레이어 탭이 열려 있는 실시간 방)인지 확인한다.
2. **탭 준비** — 이미 열려 있는 사용자의 실시간 테스트 탭(여러 개의 플레이어 탭 등)은 절대 새로고침하거나 재사용하지 않는다. 새로고침은 로비 상태에서 소켓이 끊기며 서버가 그 플레이어를 방에서 제거하는 부작용이 있다(이번 세션에서 실제로 겪은 사고). 검증용으로는 항상 **새 탭**을 만든다.
3. **화면 진입**
   - 로그인/방 생성이 필요 없는 화면(방코드 입력 등)은 바로 그 라우트로 이동해서 스크린샷.
   - 로비/대기실/게임 진행 화면처럼 실제 데이터가 있어야 의미 있는 화면은, 실제 플레이어를 여러 명 입장시키는 대신 **개발자 도구 콘솔로 상태를 주입**해서 빠르게 재현한다 (`players` 배열을 채우고 `renderGrid()`/`renderLobbyGrid()`/`renderPipBar()` 같은 렌더 함수를 직접 호출, `data-phase` 속성과 라벨 텍스트를 직접 세팅). 이 세션에서 쓴 패턴을 재사용하면 된다.
4. **가로/세로 스크롤 없는지 먼저 확인** — 스크린샷 찍기 전에 `document.documentElement.scrollWidth > window.innerWidth` / `scrollHeight > window.innerHeight`를 evaluate_script로 체크한다. 있으면 스크린샷 보내기 전에 원인을 먼저 고친다(스크린샷만 보내고 스크롤 문제를 놓치지 않는다).
5. **콘솔 에러 확인** — `list_console_messages`로 확인. `favicon.ico` 404는 이 프로젝트에서 원래부터 있던 무관한 항목이니 무시해도 된다. 그 외 에러가 있으면 스크린샷 전에 고친다.
6. **스크린샷 저장** — `take_screenshot`에 `filePath`를 지정해서 세션 스크래치 디렉터리(예: `.tmp-preview/`) 밑에 저장한다.
7. **SendUserFile로 전송** — 무엇을 고쳤는지 한 줄 캡션과 함께 보낸다. `status: "normal"` (사용자가 방금 요청한 후속 작업이므로).
8. **정리** — 전송 후 임시 스크린샷 디렉터리를 삭제한다(`rm -rf`). 테스트용으로 새로 연 탭은 다음 확인 때 재사용하거나 필요 없으면 닫는다. 단, 사용자의 실시간 테스트 탭은 절대 닫지 않는다.

## 뷰포트 선택

- 기본은 데스크톱(1440x900)과 모바일(390x844) 중 **이번에 고친 내용과 더 관련 있는 쪽 하나**만 보여준다. 레이아웃 구조를 바꾼 경우(반응형 관련 수정)라면 두 개 다 보여준다.
- 어느 쪽인지 애매하면 데스크톱을 기본으로 하고, 모바일도 궁금할 수 있다고 짧게 언급한다.

## 하지 말 것

- "커밋해도 될까요?"만 묻고 실제 화면은 안 보여주는 것.
- 사용자의 실시간 테스트 세션(여러 플레이어 탭)을 새로고침/종료해서 상태를 깨뜨리는 것.
- 스크린샷을 텍스트로만 설명하고 실제 이미지 전송을 생략하는 것.
