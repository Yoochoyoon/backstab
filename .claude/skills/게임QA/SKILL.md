# 게임QA 스킬

사용자가 실제 플레이어(또는 호스트)로 게임을 체험하는 동안, 나머지 자리는 브라우저 탭으로 자동 접속시킨 "봇"으로 채우고 게임을 끝까지 자동으로 진행시켜주는 스킬. 로비 준비까지만 도와주던 기존 `봇채우기`와 달리, **게임이 시작된 이후에도 사용자에게 묻지 않고 봇들의 밤 행동/투표와 (필요하면) 페이즈 진행까지 전부 자동으로 처리해서 게임 종료까지 끌고 간다.**

## 0. 시작하면 가장 먼저 묻는 것

**"참여자로 할지 호스트로 할지"** 딱 하나만 물어본다 (다른 확인은 아래 절차 안에서 자연스럽게 진행). 이후 어느 쪽인지에 따라 절차가 완전히 갈린다.

- **참여자** — 내가 방을 만들고 봇 7명을 채운 뒤, 방 코드를 사용자에게 준다. 사용자는 자기 기기로 8번째 플레이어로 입장한다. 이 경우 호스트 탭도 내가 직접 제어한다(방 생성, 페이즈 진행 버튼 클릭 등).
- **호스트** — 사용자가 이미 자기 기기에서 호스트로 방을 만들어뒀다는 뜻이므로, 나에게 방 코드를 물어본 뒤 그 방에 봇 8명을 채운다. 이 경우 호스트 탭은 사용자가 직접 쥐고 있으므로 나는 손대지 않는다 — 봇 8명의 밤 행동/투표만 자동으로 채워 넣는다.

두 경우 모두 목표 인원은 **총 8명**(호스트 자신은 게임 참가자 수에 포함되지 않음)으로 고정한다.

## 1. 환경 확인

로컬(`http://localhost:3000`)인지 배포판(`https://backstab-tu0e.onrender.com`)인지 확인한다. 사용자가 스마트폰으로 참여한다고 하면 배포판을 쓴다. 로컬이면 먼저 `curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/host`로 서버가 떠 있는지 확인한다.

**사용자의 다른 실시간 테스트 탭(이 QA와 무관한 host·player 탭)은 절대 재사용하거나 새로고침하지 않는다.** 애매하면 항상 새 탭을 만든다.

## 2-A. 참여자 모드 — 방 준비

1. 새 탭에서 `{origin}/host`로 이동해 `document.getElementById("createRoomBtn").click()`으로 방을 만들고, `document.getElementById("roomCode").textContent`로 방 코드를 읽는다. 이 탭이 이후 내가 계속 제어할 호스트 탭이다.
2. 봇 7명을 아래 2-C 절차대로 입장시킨다(닉네임 `봇1`~`봇7`).
3. 호스트 탭에서 `players.map(p => p.nickname)`으로 7명이 실제로 들어왔는지 검증한다.
4. 사용자에게 **"방 코드는 XXXX입니다. {player URL}에서 입장하세요."** 라고 안내하고, 사용자가 입장을 마쳤다고 확인해줄 때까지 기다린다(시작 버튼은 누르지 않는다).
5. 사용자가 입장을 마쳤다고 하거나 시작을 요청하면 호스트 탭에서 `players.length`가 8인지 한 번 더 확인한 뒤 `document.getElementById("startBtn").click()`으로 시작한다. **이 시점부터 4번(자동 진행) 절차로 넘어가고, 이후로는 사용자에게 다시 묻지 않는다.**

## 2-B. 호스트 모드 — 방 준비

1. 사용자에게 방 코드를 물어본다.
2. 봇 8명을 아래 2-C 절차대로 그 방에 입장시킨다(닉네임 `봇1`~`봇8`).
3. 봇 탭 중 하나(예: 봇1)에서 `players.map(p => p.nickname)`으로 8명이 다 들어왔는지 검증한다(호스트 탭이 내 것이 아니므로 봇 탭에서 확인).
4. 사용자에게 "봇 8명 다 넣었습니다, 시작해주세요"라고만 알리고, **여기서부터는 추가 확인 없이** 사용자가 자기 호스트 화면에서 시작하는 걸 기다린다. 게임이 시작된 걸 감지하면(아래 3번 폴링 방식) 곧바로 4번(자동 진행) 절차로 넘어간다.

## 2-C. 봇 입장 공통 절차

봇마다:
- 새 탭을 만들고 `{origin}/player`로 이동한다.
- 페이지 로드 후:
  ```js
  document.getElementById("codeInput").value = "<방코드>";
  document.getElementById("nicknameInput").value = "봇<번호>";
  document.getElementById("joinBtn").click();
  ```
- 로비 단계에서 봇 탭을 새로고침하지 않는다(새로고침하면 서버가 그 플레이어를 방에서 제거한다).

## 3. 게임 시작 감지 (호스트 모드에서만 필요)

참여자 모드는 내가 직접 `startBtn`을 누르므로 시작 시점을 이미 안다. 호스트 모드에서는 봇 탭 하나의 전역 변수를 폴링해서 시작 여부/현재 페이즈를 파악한다:
```js
({ phase: currentPhase, round: currentRound })
```
`currentPhase`가 `"lobby"`가 아니게 되면 게임이 시작된 것이다. 이후 라운드 진행 중에도 이 값으로 현재 페이즈를 계속 확인한다. 짧은 간격으로 몇 차례 재확인하면서 값이 바뀔 때마다 즉시 4번 절차로 반응한다 — 사용자(호스트)가 실제로 버튼을 눌러 페이즈를 넘기는 걸 기다리는 것이므로, 몇 초~몇십 초 정도 간격으로 확인하면 된다.

## 4. 게임 자동 진행 — **여기서부터 사용자에게 어떤 것도 묻지 않는다**

게임이 끝날 때까지 다음을 라운드마다 반복한다. 진행 상황을 매 라운드 사용자에게 중계하듯 보고하지 않는다 — 조용히 진행하고 끝나면 한 번에 요약 보고한다.

### 4-1. 밤 페이즈(`night`, 1라운드 제외 — 1라운드는 정찰 라운드라 행동 없음)

살아있는 봇 탭마다:
```js
const actionCard = [...document.querySelectorAll('#actionSection .na-skill-card')]
  .find(c => c.querySelector('.na-skill-card__title')?.textContent === '기본 공격');
actionCard.click();
const alive = players.filter(p => p.id !== myId && p.alive).map(p => p.nickname);
const targetName = alive[Math.floor(Math.random() * alive.length)];
const targetCard = [...document.querySelectorAll('#targetSection .hp-monitor-card')]
  .find(c => c.querySelector('.hp-monitor-card__name')?.textContent === targetName);
targetCard.click();
document.getElementById('submitBtn').click();
```
기본 공격 + 살아있는 다른 플레이어 중 무작위 대상으로 고정한다(특수 능력 카드까지 무작위로 골라 쓰면 쉴드/서약처럼 대상 지정이 다른 액션과 섞여 로직이 복잡해지므로, 기본은 항상 기본 공격으로 통일한다).

### 4-2. 투표 페이즈(`day_vote`)

살아있는 봇 탭마다, 살아있는 다른 플레이어 중 무작위 대상에게 투표(위와 같은 방식으로 `#targetSection` 카드 클릭 후 `submitBtn` 클릭). 동점 재투표라 `voteAllowedTargetIds`로 대상이 좁혀졌으면 그 목록 안에서만 고른다.

### 4-3. 페이즈 진행

- **참여자 모드(호스트 탭을 내가 제어)**: 살아있는 봇 전원이 제출을 마치면(사용자 본인 제출은 기다리지 않음 — 실제 플레이어인 사용자가 알아서 제출한다) 곧바로 호스트 탭에서 `document.getElementById("advanceBtn").click()`으로 다음 단계로 넘긴다. 타이머 만료를 기다리지 않는다.
- **호스트 모드**: 내가 호스트 탭을 건드릴 수 없으므로, 봇 제출까지만 마치고 사용자(호스트)가 직접 다음 단계로 넘길 때까지 3번 절차로 돌아가 조용히 폴링한다.

### 4-4. 종료 감지

봇 탭(또는 참여자 모드의 호스트 탭)에서 `overSection`(플레이어 화면) 또는 `data-phase="game_over"`(호스트 화면)이 나타나면 게임 종료다. 승자와 최종 결과를 확인한다.

### 4-5. 안전장치

라운드가 15를 넘어가는데도 게임이 끝나지 않으면(무한 루프 방지) 진행을 멈추고 현재 상태를 사용자에게 보고한다 — 이건 "개입을 묻지 않는다" 규칙의 예외로, 실제로 뭔가 멈춘 것으로 판단되는 경우다.

## 5. 게임 종료 후

탭 정리(봇 탭들을 닫음, 사용자가 계속 보고 싶어할 수도 있으니 먼저 닫아도 되는지 확인 없이 진행하되 호스트/사용자 본인 탭은 절대 닫지 않는다)를 마친 뒤, **사용자에게 개선사항을 묻는다** — 예: "게임 플레이해보니 어떠셨나요? 고쳤으면 하는 부분이나 불편했던 점 있으신가요?"

## 주의

- **여러 탭이 같은 브라우저의 `localStorage`를 공유한다.** 지금은 세션을 탭 전용 `sessionStorage`에 우선 저장하도록 고쳐놔서 탭끼리 서로의 세션을 덮어쓰지 않지만, 봇 탭에서 `localStorage.clear()`를 돌릴 때는 `sessionStorage`도 같이 지워야 그 탭이 깨끗한 상태로 시작한다. 재접속 관련 동작을 테스트할 때 결과가 이상하면 이 부분을 먼저 의심한다.
- 로비 단계에서 봇 탭을 새로고침해도 이제는 플레이어가 유지된다(1분 유예 후 미복귀 시에만 제거). 다만 불필요한 새로고침은 여전히 피한다.
- 게임 중간에 봇 탭을 닫지 않는다 — 그 플레이어가 방에서 빠져나가며 흐름이 깨진다.
- 닉네임은 방마다 새로 발급한다(같은 방 안에서만 중복 닉네임이 거부됨).
- 사용자 본인이 조작 중인 탭(참여자 모드의 사용자 폰, 호스트 모드의 사용자 호스트 탭)은 내가 절대 클릭·새로고침하지 않는다.
