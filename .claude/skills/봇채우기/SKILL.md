# 봇채우기 스킬

사용자가 실제 플레이어로 게임을 체험해보고 싶을 때, 나머지 자리를 브라우저 탭으로 자동 접속시킨 "봇" 플레이어로 채워준다. 사용자는 자기 기기(주로 스마트폰)로 직접 입장하고, 나는 나머지를 채운다.

## 시작 전 확인할 것 (모호하면 사용자에게 물어본다)

1. **어느 환경인가** — 로컬(`http://localhost:3000`) vs 배포판(`https://backstab-tu0e.onrender.com`). 사용자가 "로컬로 할 환경이 안 됐다"거나 스마트폰으로 접속한다고 하면 배포판을 쓴다. 로컬이면 `npm run dev`가 떠 있는지 먼저 `curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/host`로 확인한다.
2. **직접 들어올 사람이 몇 명인가** — 보통 사용자 1명. 봇 개수 = 목표 인원 − 직접 들어올 인원. 목표 인원은 별 말이 없으면 `MIN_PLAYERS`(6명)로 채운다. 사용자가 "8명으로", "최대인원으로" 등 다르게 말하면 그에 맞춘다(`MIN_PLAYERS`~`MAX_PLAYERS`, 6~10).
3. **이미 만든 방이 있는가** — 사용자가 방 코드를 알려주면 새로 만들지 않고 그 방에 봇만 채운다. 없으면 새로 만든다.

## 절차

1. **호스트 탭 준비**
   - 이미 열려 있는 호스트 탭(해당 환경의 `/host`, 아직 방을 만들지 않은 상태)이 있으면 재사용하고, 없으면 새 탭을 만들어 `{origin}/host`로 이동한다.
   - **사용자의 실시간 테스트 탭(다른 방/다른 목적으로 열려 있는 host·player 탭)은 절대 재사용하거나 새로고침하지 않는다.** 애매하면 새 탭을 만든다.
2. **방 생성 또는 기존 방 확인**
   - 새로 만드는 경우: `document.getElementById("createRoomBtn").click()`으로 방을 만든다(버튼 좌표 클릭 대신 JS로 직접 클릭하면 더 안정적).
   - 방 코드는 `document.getElementById("roomCode").textContent`로 읽는다.
   - 기존 방을 쓰는 경우: 사용자가 준 코드를 그대로 쓰고, 호스트 탭은 그 방의 로비 화면이어야 한다(진행 중인 방이면 새 플레이어가 못 들어오니 주의).
3. **봇 개수만큼 반복** (각 봇마다):
   - 새 탭을 만들고 `{origin}/player`로 이동한다.
   - 페이지 로드 후 다음을 실행한다:
     ```js
     document.getElementById("codeInput").value = "<방코드>";
     document.getElementById("nicknameInput").value = "봇<번호>";
     document.getElementById("joinBtn").click();
     ```
   - 닉네임은 `봇1`, `봇2`... 순번으로 붙인다(최대 7자 제한 안에 들어옴).
4. **검증** — 호스트 탭에서 `players.map(p => p.nickname)`을 확인해 봇이 실제로 다 들어왔는지 확인한다. 에러가 있으면(닉네임 중복, 방 꽉 참 등) 원인을 보고 재시도한다.
5. **사용자에게 방 코드 전달** — "방 코드는 XXXX입니다. {player URL}에서 입장하세요"라고 안내한다.
6. **게임 시작은 자동으로 누르지 않는다** — 사용자가 직접 입장할 시간이 필요하고, "시작해줘"라고 명시적으로 말하기 전까지는 진행자 화면의 시작 버튼을 누르지 않는다. 사용자가 입장을 마쳤다고 하거나 시작을 요청하면 그때 `document.getElementById("startBtn").click()`으로 시작한다.

## 주의

- 봇 탭들은 테스트가 끝나면 정리(닫기)해도 되지만, **사용자가 계속 진행 중이면 먼저 물어보고 닫는다** — 방 중간에 봇 탭을 닫으면 그 플레이어가 방에서 빠져나가면서 게임 흐름이 깨질 수 있다.
- 로비 단계에서 봇 탭을 새로고침하면 그 플레이어가 방에서 제거된다(서버 쪽 동작) — 절대 새로고침하지 않는다.
- 닉네임은 항상 방마다 겹치지 않게 새로 발급한다(예: 이전 방에서 쓰던 "봇1"을 다른 방에 재사용해도 상관없지만, 같은 방 안에서는 중복 닉네임이 거부된다).
