# BACKSTEP 게임 UI 디자인 시스템

> **문서 목적**
>
> 기존에 제작된 BACKSTEP 화면의 시각 언어를 다른 모든 화면에 일관되게 적용하기 위한 UI/UX 디자인 기준서다. 본 문서는 메인 화면, 방 생성, 대기실, 플레이어 선택, 게임 진행, 결과, 설정, 튜토리얼 등 확장 화면을 제작할 때 사용할 수 있는 공통 규칙을 정의한다.

---

## 1. 디자인 콘셉트

### 1.1 핵심 키워드

- **레트로 아케이드 게임**
- **90년대 게임 패키지와 만화책의 혼합**
- **거칠고 강한 인쇄물 질감**
- **검정·버건디·백색 중심의 고대비 화면**
- **노란색을 이용한 행동 유도**
- **코믹북 패널과 찢어진 종이 조각**
- **긴장감 있는 대결과 은밀한 심리전**
- **조금 투박하지만 의도적으로 만든 아날로그 감성**

### 1.2 한 문장 정의

> 검은 배경 위에 버건디 종이를 찢어 붙이고, 흰색 외곽선과 만화식 도트 이미지를 배치한 레트로 심리 게임 인터페이스.

### 1.3 디자인이 전달해야 하는 감정

1. 처음 진입했을 때는 **강한 제목과 대비**로 게임의 존재감을 전달한다.
2. 방을 만들거나 참가할 때는 **낡은 게임 포스터를 조작하는 느낌**을 준다.
3. 플레이어를 선택할 때는 **범죄 수배 카드 또는 캐릭터 컬렉션**을 확인하는 느낌을 준다.
4. 실제 게임 중에는 장식보다 **긴장감, 정보, 선택 결과**가 먼저 보이도록 한다.
5. 모든 버튼은 클릭할 때 **기계식·아케이드식 반응**을 느낄 수 있어야 한다.

## 2. 시각 언어의 우선순위

모든 화면은 아래 순서로 디자인한다.

1. **검은색 화면 바탕**으로 전체 분위기를 고정한다.
2. 화면의 주요 영역에 **버건디 종이 패널**을 배치한다.
3. 패널의 모서리나 가장자리에 **사선, 찢어진 종이, 흰색 테두리**를 적용한다.
4. 주요 제목은 **흰색 또는 노란색**, 검정 외곽선과 함께 사용한다.
5. 보조 정보는 버건디와 흰색의 명도 차이로 구분한다.
6. 사용자의 다음 행동은 노란색 강조 버튼 하나로 유도한다.

> 한 화면에서 강한 강조색을 여러 개 사용하지 않는다. 기본 강조색은 노란색 하나만 유지한다.

## 3. 컬러 시스템

### 3.1 기본 색상 토큰

| 토큰 | 색상 | 권장 용도 |
|---|---|---|
| `black-900` | `#000000` | 전체 배경, 강한 외곽선, 본문 대비 영역 |
| `black-800` | `#111111` | 입력창, 리스트, 비활성 패널 |
| `burgundy-900` | `#54161B` | 종이 질감의 가장 어두운 부분, 깊은 그림자 |
| `burgundy-800` | `#6E2025` | 기본 버건디 패널 |
| `burgundy-700` | `#82363A` | 패널의 밝은 면, 카드 배경 |
| `burgundy-600` | `#94484A` | 보조 패널, 선택 상태의 배경 |
| `paper-white` | `#F4F4F0` | 제목, 테두리, 카드 하단 라벨 |
| `pure-white` | `#FFFFFF` | 강한 텍스트, 주요 외곽선 |
| `action-yellow` | `#FFE500` | 시작, 확인, 선택, 다음 버튼 |
| `yellow-dark` | `#BFA800` | 노란색 버튼의 눌림 상태, 보조 강조 |
| `muted-gray` | `#A5A0A0` | 비활성 텍스트, 설명, 플레이어 대기 상태 |
| `danger-red` | `#B62F32` | 오류, 퇴장, 위험 상태. 아주 제한적으로 사용 |

### 3.2 색상 비율

권장 화면 비율은 다음과 같다.

- 검정: **45~60%**
- 버건디: **25~40%**
- 흰색: **8~15%**
- 노란색: **2~8%**
- 기타 색상: **5% 미만**

### 3.3 색상 사용 규칙

- 노란색은 **현재 화면에서 가장 중요한 행동**에만 사용한다.
- 노란색 버튼을 한 화면에 여러 개 둘 경우, 주 버튼과 보조 버튼의 위계를 명확하게 구분한다.
- 버건디 패널 위의 본문은 흰색 또는 `paper-white`를 사용한다.
- 검정 배경 위의 제목은 흰색을 기본으로 하고, 필요한 경우 검정 그림자를 추가한다.
- 회색 텍스트는 보조 설명에만 사용한다. 중요한 정보는 회색으로 작성하지 않는다.
- 순수한 빨강·파랑·초록을 기본 UI 색으로 사용하지 않는다. 기존 분위기를 깨뜨릴 수 있다.

## 4. 배경 및 텍스처

### 4.1 전체 배경

- 기본 배경은 완전한 검정 `#000000`이다.
- 단색 검정이 너무 비어 보일 경우, 아주 낮은 불투명도의 노이즈를 추가한다.
- 화면 전체에 강한 그라디언트를 적용하지 않는다.
- 콘텐츠가 없는 공간은 의도적인 여백으로 유지한다.

### 4.2 버건디 종이 패널

버건디 패널은 단순한 사각형이 아니라 다음 요소를 포함한다.

- 종이 구김 질감
- 불규칙한 명도 변화
- 약한 얼룩과 인쇄 노이즈
- 가장자리의 불완전한 절단선
- 일부 영역의 투명한 검정 오버레이

권장 CSS 표현 예시:

```css
.paper-panel {
  background-color: #6e2025;
  background-image:
    linear-gradient(135deg, rgba(255,255,255,.04), transparent 35%),
    linear-gradient(320deg, rgba(0,0,0,.18), transparent 42%),
    url('/textures/crumpled-paper.png');
  background-size: cover;
  background-blend-mode: soft-light, multiply, multiply;
}
```

### 4.3 질감 강도

- 메인 타이틀 영역: 강한 질감
- 입력 폼 영역: 중간 질감
- 대기실 리스트: 약한 질감
- 실제 게임 플레이 영역: 약한 질감 또는 제거

텍스처가 글자를 방해하면 안 된다. 글자와 입력창이 있는 영역에는 검정 반투명 레이어를 추가해 가독성을 확보한다.

## 5. 형태 및 레이아웃

### 5.1 기본 형태

화면의 기본 형태는 다음 세 가지를 조합한다.

1. **직사각형**: 입력창, 리스트, 방 정보, 설명 패널
2. **둥근 모서리 카드**: 플레이어 카드, 버튼, 캐릭터 선택
3. **사선형 종이 조각**: 화면 전환, 섹션 분리, 분위기 연출

### 5.2 모서리 규칙

- 메인 버튼: `12~18px`
- 입력창: `12~16px`
- 플레이어 카드: `16~22px`
- 대형 패널: `0~8px` 또는 사선 절단
- 완전히 둥근 필 형태는 사용하지 않는다. 너무 현대적인 SaaS UI처럼 보일 수 있다.

### 5.3 사선 요소

사선은 BACKSTEP의 중요한 시각적 특징이다.

- 패널의 좌측 상단 또는 우측 하단을 사선으로 자른다.
- 사선 각도는 **8~18도** 범위에서 사용한다.
- 하나의 화면에서 사선 방향은 가능하면 통일한다.
- 사선 테두리는 흰색 3~6px로 표현한다.
- 사선은 장식용뿐 아니라 콘텐츠 그룹을 구분하는 역할도 한다.

CSS 예시:

```css
.diagonal-panel {
  clip-path: polygon(0 0, 94% 0, 100% 10%, 100% 100%, 6% 100%, 0 90%);
  border: 0;
  position: relative;
}

.diagonal-panel::after {
  content: '';
  position: absolute;
  inset: 0;
  pointer-events: none;
  border: 4px solid #f4f4f0;
  clip-path: polygon(0 0, 94% 0, 100% 10%, 100% 100%, 6% 100%, 0 90%);
}
```

### 5.4 화면 여백

- 화면 가장자리 기본 여백: `24~48px`
- 모바일 화면 가장자리: `16~24px`
- 제목과 본문 사이: `16~28px`
- 섹션 사이: `32~64px`
- 카드 사이: `12~20px`

공간을 모두 채우지 않는다. 검정 여백은 디자인의 일부다.

## 6. 타이포그래피

### 6.1 서체 방향

폰트는 다음 성격을 만족해야 한다.

- 굵고 넓은 제목
- 만화책·아케이드 포스터와 어울리는 강한 획
- 한글 본문은 읽기 쉬운 고딕체
- 제목은 영문과 한글 모두 외곽선 처리가 가능해야 함

권장 조합:

- 영문 로고: `Anton`, `Impact`, `Bebas Neue`, `Arial Black`
- 한글 제목: 굵은 고딕 계열 또는 각진 디스플레이 서체
- 본문: `Pretendard`, `Noto Sans KR`, `NanumGothic`
- 숫자·방 코드: 고정폭 느낌이 있는 굵은 고딕

### 6.2 글자 스타일

#### 메인 로고

- 대문자 사용: `BACKSTEP`
- 글자 색상: 흰색
- 외곽선: 검정 5~9px
- 약한 흰색 내부 하이라이트 허용
- 자간: `0.04em~0.12em`
- 각 글자는 약간씩 불규칙하게 배치해 손으로 만든 포스터 느낌을 줄 수 있음

#### 화면 제목

- 색상: 흰색
- 검정 외곽선: 3~6px
- 살짝 기울이거나 기준선을 흔들어도 됨
- 제목은 장식이 아니라 현재 화면의 목적을 알려야 함

예시:

- `방 만들기`
- `대기실`
- `플레이어 선택`
- `작전 개시`
- `결과 보고서`

#### 일반 라벨

- 흰색 또는 `paper-white`
- 글자 크기: `14~18px`
- 굵기: `600~700`
- 입력 안내 문구는 너무 작게 만들지 않는다.

#### 안내 문구

- 색상: 흰색 또는 연한 회색
- 글자 크기: `13~16px`
- 줄 간격: `1.5~1.8`
- 한 문장에 하나의 행동만 안내한다.

### 6.3 외곽선 텍스트

```css
.comic-text {
  color: #fff;
  font-weight: 900;
  text-shadow:
    -3px -3px 0 #000,
     3px -3px 0 #000,
    -3px  3px 0 #000,
     3px  3px 0 #000,
     0 5px 0 rgba(0,0,0,.35);
}
```

작은 본문에는 두꺼운 외곽선을 적용하지 않는다. 20px 이상인 제목·강조 문구에만 사용한다.

## 7. 버튼 디자인

### 7.1 기본 버튼 구조

버튼은 다음 구조를 갖는다.

- 검정 또는 버건디 내부
- 두꺼운 흰색 또는 노란색 테두리
- 굵은 글자
- 눌림에 따른 위치 변화
- 짧고 명확한 동사형 라벨

권장 높이:

- 모바일 기본 버튼: `48~56px`
- 데스크톱 기본 버튼: `52~64px`
- 작은 보조 버튼: `36~44px`

### 7.2 주요 버튼

주요 행동에는 노란색 테두리를 사용한다.

```css
.primary-button {
  min-height: 56px;
  padding: 0 28px;
  color: #ffe500;
  background: #050505;
  border: 5px solid #ffe500;
  border-radius: 14px;
  font-weight: 900;
  letter-spacing: .04em;
  transition: transform .12s ease, background .12s ease, color .12s ease;
}

.primary-button:hover,
.primary-button:focus-visible {
  color: #000;
  background: #ffe500;
  transform: translateY(-2px);
}

.primary-button:active {
  transform: translateY(3px);
  box-shadow: inset 0 3px 0 rgba(0,0,0,.35);
}
```

### 7.3 보조 버튼

- 흰색 테두리 + 검정 내부
- 텍스트는 흰색
- 뒤로 가기, 취소, 목록으로 이동 등에 사용

### 7.4 버튼 라벨 규칙

좋은 예:

- `방 만들기`
- `참가하기`
- `시작`
- `확인`
- `다음`
- `게임 나가기`

피해야 할 예:

- `여기를 눌러주세요`
- `확인하기 버튼`
- `진행`
- `Submit`

### 7.5 버튼 상태

| 상태 | 표현 |
|---|---|
| 기본 | 검정 내부 + 노란색 테두리 |
| 호버 | 노란색 내부 + 검정 글자 |
| 포커스 | 노란색 외곽 링 3px 추가 |
| 눌림 | 아래로 2~4px 이동, 그림자 감소 |
| 비활성 | 회색 테두리와 45% 불투명도 |
| 로딩 | 버튼 폭 유지, 텍스트 대신 점 3개 또는 짧은 로딩 문구 |
| 오류 | 버튼 주변에 짧은 붉은 경고 문구 표시 |

## 8. 입력창 및 폼

### 8.1 입력창

입력창은 현대적인 흰색 폼보다, 포스터 위에 붙인 검은 라벨판처럼 보여야 한다.

- 배경: 검정 또는 아주 어두운 버건디
- 테두리: 흰색 2~4px
- 모서리: `12~16px`
- 내부 여백: 좌우 `18~22px`
- 최소 높이: `48px`
- 입력 텍스트: 흰색
- 플레이스홀더: 회색

```css
.input-field {
  width: 100%;
  min-height: 50px;
  padding: 12px 18px;
  color: #fff;
  background: #111;
  border: 3px solid #f4f4f0;
  border-radius: 14px;
  outline: none;
}

.input-field:focus {
  border-color: #ffe500;
  box-shadow: 0 0 0 4px rgba(255,229,0,.2);
}
```

### 8.2 라벨 배치

- 라벨은 입력창 위에 둔다.
- 라벨과 입력창 사이 간격: `8~10px`
- 예시 문구는 중앙 정렬보다 좌측 정렬을 기본으로 한다.
- 기존 화면처럼 장식성이 필요한 경우, 라벨을 중앙 정렬하고 입력창 아래에 짧은 밑줄을 배치할 수 있다.

### 8.3 검증 메시지

- 오류는 입력창 바로 아래에 배치한다.
- 오류 문구는 짧고 구체적으로 쓴다.
- 예: `방 코드는 6자리 숫자여야 합니다.`
- 오류 상태에서도 레이아웃이 갑자기 크게 밀리지 않도록 메시지 영역을 예약한다.

## 9. 카드와 플레이어 컴포넌트

### 9.1 플레이어 카드

플레이어 카드는 기존 화면의 핵심 요소다.

구성:

1. 검정 또는 어두운 버건디 카드 배경
2. 두꺼운 흰색 외곽선
3. 캐릭터 이미지
4. 카드 하단의 흰색 이름 라벨
5. 선택 또는 준비 상태 표시

권장 비율:

- 카드 전체: `4 : 5`
- 이미지 영역: 전체 높이의 `78~84%`
- 이름 라벨: 전체 높이의 `16~22%`

### 9.2 카드 상태

| 상태 | 시각 표현 |
|---|---|
| 기본 | 흰색 테두리, 정상 밝기 |
| 호버 | 위로 4px 이동, 외곽선 두께 증가 |
| 선택됨 | 노란색 테두리, 내부에 노란색 그림자 |
| 준비 완료 | 카드 우측 상단에 노란색 `READY` 배지 |
| 본인 카드 | 하단에 `YOU` 라벨 추가 |
| 비어 있음 | 점선 테두리, 어두운 실루엣 |
| 접속 끊김 | 이미지 어둡게, 회색 `OFFLINE` 라벨 |

### 9.3 캐릭터 이미지 스타일

- 흑백 또는 제한된 색상
- 만화식 하프톤 도트
- 얼굴과 실루엣이 한눈에 구분되어야 함
- 이미지마다 배경색을 다르게 하지 않는다.
- 캐릭터의 외곽선은 검정으로 통일한다.
- 이미지가 카드 영역을 넘더라도 흰색 프레임은 유지한다.

### 9.4 이름 라벨

- 배경: 흰색
- 글자: 검정
- 굵기: `700~900`
- 긴 이름은 한 줄 말줄임표 처리
- 이름이 비어 있으면 `이름 없음` 대신 입력 전 상태를 명확히 보여준다.

## 10. 화면별 디자인 방향

## 10.1 메인 화면

### 목적
게임의 분위기와 타이틀을 강하게 전달하고, 사용자가 곧바로 방을 만들거나 참가하도록 한다.

### 구성

- 검정 전체 배경
- 중앙 또는 좌측의 큰 `BACKSTEP` 로고
- 버건디 종이 패널
- 상단 또는 좌측의 캐릭터 도트 이미지
- 반대편에 다른 캐릭터 실루엣
- 로고 아래의 `방 만들기` 주요 버튼
- 패널 가장자리에 흰색 사선 테두리

### 동작

- 로고는 화면 진입 시 100% 크기로 튀어나오는 짧은 애니메이션을 사용한다.
- 버튼은 마우스 오버 시 노란색이 번지는 효과를 사용한다.
- 배경 질감은 움직이지 않거나 아주 느리게 흔들린다.

---

## 10.2 방 만들기 화면

### 목적
최소한의 입력만으로 방을 생성하게 한다.

### 구성

- 세로형 버건디 패널
- 상단 제목: `방 만들기`
- 방 코드 입력 영역
- 이름 입력 영역
- 하단 주요 버튼: `시작`
- 좌측 또는 우측에 사선으로 잘린 흰색 프레임

### UX 규칙

- 필수 정보는 최대 2~3개로 제한한다.
- 입력 순서는 `방 코드 → 이름 → 시작`으로 고정한다.
- 입력하지 않은 항목이 있으면 버튼을 비활성화하기보다 오류 이유를 보여준다.
- 방 코드 입력은 숫자 키패드와 붙여넣기를 모두 지원한다.

---

## 10.3 대기실 화면

### 목적
참여자와 현재 상태를 한눈에 보여주고, 게임 시작 시점을 명확히 알린다.

### 구성

- 상단: `대기중` 또는 `대기실`
- 중앙: `진행자가 시작하면 자동으로 시작됩니다.`
- 하단 또는 중앙: 참여자 리스트
- 리스트의 각 행: 번호, 이름, 연결 상태
- 방 코드와 복사 버튼
- 진행자에게만 `게임 시작` 버튼 표시

### 리스트 디자인

- 전체 리스트는 검정 카드 위에 배치한다.
- 각 행 사이에 얇은 버건디 구분선을 넣는다.
- 선택된 진행자 행에는 노란색 작은 아이콘을 붙인다.
- 리스트가 길어지면 패널 내부에서 스크롤한다.
- 모바일에서는 리스트가 화면 높이의 45~55%를 넘지 않도록 한다.

---

## 10.4 플레이어 선택 화면

### 목적
참여자가 자신의 캐릭터 또는 플레이어 슬롯을 선택하고 준비 상태를 전달한다.

### 구성

- 대형 제목: `입장할 플레이어`
- 5열 또는 반응형 그리드
- 각 카드에 캐릭터 이미지와 이름
- 하단 좌측에 방 코드
- 하단 우측에 `선택 완료` 또는 `시작`

### 반응형 그리드

- 데스크톱: 5열
- 태블릿: 3~4열
- 모바일: 2열
- 카드가 지나치게 작아지면 열 수를 줄인다.
- 이름 라벨은 항상 카드 하단에 고정한다.

### 선택 애니메이션

- 선택 전: 흰색 테두리
- 선택 순간: 노란색 테두리와 120ms 확대
- 선택 완료: 카드 위에 노란색 체크 표시
- 다른 사용자가 선택한 카드: 어두운 오버레이와 작은 이름 배지

---

## 10.5 게임 진행 화면

게임이 시작되면 장식보다 정보 전달을 우선한다.

### 기본 구조

- 상단: 현재 라운드, 남은 시간, 방 코드
- 중앙: 문제 또는 사건 설명
- 좌측: 현재 플레이어 또는 내 상태
- 우측: 선택지·행동 패널
- 하단: 채팅, 로그, 다음 행동 버튼

### 화면 분위기

- 버건디 패널의 질감을 약하게 줄인다.
- 선택 가능한 정보는 흰색 카드로 구분한다.
- 위험하거나 시간이 임박한 경우 노란색을 깜빡이게 하지 말고, 테두리 두께와 짧은 모션으로 강조한다.
- 정보가 많을 때는 장식 요소를 숨길 수 있어야 한다.

### 게임 중 버튼

- 버튼 라벨은 행동 중심으로 작성한다.
- 예: `의심하기`, `단서 확인`, `투표하기`, `다음으로`, `확정`
- 취소·뒤로 가기는 보조 버튼으로 작게 배치한다.

---

## 10.6 결과 화면

### 목적
결과를 명확하게 전달하면서도 승패의 극적인 느낌을 유지한다.

### 구성

- 상단 큰 결과 제목: `작전 성공`, `작전 실패`, `BACKSTEP`
- 중앙에 승리 팀 또는 핵심 플레이어
- 좌우 또는 하단에 결과 요약
- 플레이어별 점수·역할·기여도
- 하단 버튼: `다시 하기`, `대기실로`, `메인으로`

### 결과별 컬러

- 성공: 노란색을 제목과 핵심 수치에 사용
- 실패: 버건디와 흰색 중심, 노란색 사용량 감소
- 무승부: 흰색 중심, 얇은 노란색 포인트

---

## 10.7 설정 화면

### 구성

- 버건디 패널 안에 설정 항목을 세로로 배치
- 사운드, 진동, 언어, 접근성, 게임 나가기
- 토글은 일반 모바일 토글보다 사각형 아케이드 스위치 형태로 만든다.
- 저장 버튼은 노란색 주요 버튼으로 유지한다.

### 토글 상태

- 켜짐: 노란색 핸들 또는 노란색 테두리
- 꺼짐: 회색 핸들, 검정 내부
- 포커스: 흰색 외곽 링

## 11. 아이콘과 그래픽 요소

### 11.1 아이콘 스타일

- 선 두께가 굵은 픽토그램
- 검정·흰색·노란색 3색 이내
- 둥글고 귀여운 아이콘보다 각지고 만화적인 형태
- 아이콘만으로 의미가 불분명하면 짧은 텍스트를 함께 표시

### 11.2 추천 아이콘

- 방 코드: 열쇠, 태그, 숫자판
- 복사: 겹친 종이
- 진행자: 별 또는 왕관
- 준비 완료: 체크 배지
- 연결 상태: 전파 또는 점
- 나가기: 찢어진 문, 화살표
- 경고: 느낌표가 들어간 삼각형

### 11.3 장식 그래픽

- 검은 반점
- 하프톤 원형 패턴
- 찢어진 종이 모서리
- 짧은 속도선
- 만화식 `WAIT`, `READY`, `GO`, `NEXT` 텍스트
- 낡은 인쇄물의 미세한 어긋남

장식은 정보보다 앞에 나오지 않아야 한다. 클릭 가능한 요소와 장식 그래픽은 명확히 구분한다.

## 12. 모션 및 인터랙션

### 12.1 기본 모션 원칙

- 빠르고 짧다.
- 기계적이지만 지나치게 매끄럽지 않다.
- 화면 전환은 종이 패널이 밀려오는 듯한 느낌을 준다.
- 모든 모션은 사용자의 상태 변화를 설명해야 한다.

### 12.2 권장 시간

| 모션 | 시간 |
|---|---:|
| 버튼 호버 | 100~140ms |
| 버튼 눌림 | 80~120ms |
| 카드 선택 | 120~180ms |
| 토스트 등장 | 180~240ms |
| 패널 전환 | 260~420ms |
| 결과 연출 | 500~800ms |

### 12.3 화면 전환

권장 전환 방식:

1. 검정 화면이 잠깐 노출된다.
2. 버건디 종이 조각이 좌우 또는 대각선 방향으로 들어온다.
3. 제목이 1~2프레임 늦게 나타난다.
4. 주요 콘텐츠가 짧게 튀어나온다.

### 12.4 피해야 할 모션

- 지속적으로 흔들리는 배경
- 긴 페이드인
- 과도한 줌인·줌아웃
- 화면 전체를 가리는 번쩍임
- 색약 사용자가 구분하기 어려운 색상만으로 상태를 표현하는 방식

## 13. 반응형 디자인

### 13.1 브레이크포인트

```css

:root {
  --breakpoint-tablet: 768px;
  --breakpoint-desktop: 1100px;
  --breakpoint-wide: 1440px;
```

### 13.2 모바일

- 콘텐츠를 한 열로 구성한다.
- 큰 로고는 화면 폭의 80~90%를 넘지 않게 한다.
- 주요 버튼은 폭을 넓혀 엄지손가락으로 누르기 쉽게 한다.
- 카드 그리드는 2열을 기본으로 한다.
- 화면 하단 고정 버튼을 사용할 수 있다.
- 가로 스크롤은 사용하지 않는다.

### 13.3 태블릿

- 입력 패널과 보조 그래픽을 좌우로 나눌 수 있다.
- 카드 그리드는 3~4열을 사용한다.
- 대기실에서는 정보 패널과 참여자 리스트를 45:55 비율로 나눈다.

### 13.4 데스크톱

- 넓은 검정 여백을 적극적으로 활용한다.
- 콘텐츠 최대 너비는 `1280~1440px`로 제한한다.
- 메인 화면은 비대칭 레이아웃을 사용한다.
- 왼쪽에 타이틀, 오른쪽에 조작 패널을 배치하는 구성이 적합하다.

## 14. 접근성

### 14.1 명도 대비

- 본문은 버건디 위에서 충분히 밝은 흰색을 사용한다.
- 노란색 텍스트를 흰색 배경 위에 직접 사용하지 않는다.
- 선택 상태는 색상뿐 아니라 테두리·체크·텍스트로도 표현한다.

### 14.2 키보드 접근성

- 모든 버튼과 카드에 포커스가 가능해야 한다.
- 포커스 링은 노란색 또는 흰색 3px 이상으로 표시한다.
- 탭 이동 순서는 화면의 읽는 순서와 일치해야 한다.

### 14.3 모션 감소

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

### 14.4 텍스트 접근성

- 장식용 영문 제목과 실제 기능 설명을 분리한다.
- `READY`, `WAIT` 같은 영문 상태에는 한글 보조 설명을 제공한다.
- 텍스트가 이미지 안에만 존재하지 않도록 한다.

## 18. 최종 디자인 원칙

1. **검정 여백을 두려워하지 않는다.** 검정은 비어 있는 공간이 아니라 BACKSTEP의 무대다.
2. **버건디는 종이처럼 보여야 한다.** 평범한 카드 배경이 되면 안 된다.
3. **흰색 외곽선은 화면을 묶는 접착제다.** 패널과 카드의 경계를 확실히 만든다.
4. **노란색은 사용자의 다음 행동을 알려준다.** 장식용으로 남발하지 않는다.
5. **제목은 크고 과감하게, 정보는 차분하고 명확하게 표현한다.**
6. **비대칭은 허용하지만 기능 흐름은 정돈한다.** 시각적으로 거칠어도 사용성은 정확해야 한다.
7. **모든 화면에 같은 질감·테두리·버튼 반응을 반복한다.** 반복이 곧 세계관의 일관성이다.
8. **아날로그 감성을 표현하되, 조작은 현대적으로 편해야 한다.**
9. **게임 진행 화면에서는 장식보다 상황 이해와 선택을 우선한다.**
10. **사용자가 지금 어디에 있고 다음에 무엇을 해야 하는지 항상 알 수 있어야 한다.**

## 19. 권장 화면 제작 순서

1. 검정 배경과 기본 그리드 작성
2. 버건디 종이 패널 배치
3. 사선 테두리와 찢어진 종이 요소 추가
4. 제목 및 섹션 헤더 적용
5. 입력창·카드·리스트 등 기능 컴포넌트 배치
6. 노란색 주요 행동 버튼 추가
7. 캐릭터 도트 이미지와 하프톤 장식 적용
8. 상태별 인터랙션 구현
9. 모바일·태블릿·데스크톱 반응형 조정
10. 접근성·가독성·게임 흐름 검수

> 새로운 화면을 만들 때 기존 화면을 그대로 복사하기보다, **색상·질감·테두리·타이포그래피·버튼 반응**을 재사용하고 화면 목적에 맞게 레이아웃만 변형한다.
