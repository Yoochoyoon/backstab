## 개요

앱/TV 연동을 직접 개발하는 웹앱+서버 수준으로 구현하기로 하고, 참가 방식·진행 통제·사망자 화면 처리·TV와 앱의 역할 분담을 확정했다.

## 결정 사항

* **기술 수준:** 각 플레이어가 스마트폰 브라우저로 접속하는 **웹앱**과, 이를 총괄하는 **중앙 서버**를 직접 개발한다. TV는 서버에 연결된 공용 화면(방송용 클라이언트)으로 취급한다. 지금까지 정한 동시 지목·자동 데미지 합산·데미지 결과 자동 공개 같은 기획을 그대로 구현할 수 있는 수준.
* **참가 방식:** 계정가입 없이 **방 코드 + 닉네임**만으로 입장한다.
* **진행 통제:** 각 페이즈(밤/토론/투표)에 **내장 타이머**가 있지만, **진행자(호스트) 역할**이 별도 관리 화면에서 타이머를 무시하고 단계를 **먼저 끝내거나 연장**할 수 있다.
* **진행자 필수 여부:** 완전 자동 모드는 지원하지 않는다 — **항상 진행자 1명이 필요하다고 전제**한다. 진행자도 보스/조직원 등 역할을 겸해 플레이에 참가할 수 있다.
* **재접속 처리:** 연결이 끊긴 플레이어가 같은 방 코드로 **같은 닉네임을 입력해 재입장하면**, 서버가 기존 플레이어로 인식해 HP·역할·생존 여부 등 기존 상태로 **자동 복귀**시킨다. 다른 기기로 들어와도 무방하다.
* **사망자 화면 처리:** 사망 시 앱이 사망 안내를 띄운 뒤, 투표·능력 버튼이 모두 **비활성화된 관전 모드**로 자동 전환된다(진행자 개입 불필요).
* **TV vs 앱 역할 분담:**
  * **TV(공용 화면):** 모두가 동시에 알아야 하는 공개 정보 — 보스 정체 공개, 현재 라운드/페이즈, 타이머, 밤 데미지 결과, 투표/심판 결과.
  * **앱(개인 화면):** 나만 알아야 하는 비공개 조작/정보 — 밤 능력·기본공격 대상 지목, 본인 HP·역할, 스파이 동료 확인 등.

## 상세 규칙/수치

| 화면 | 표시/조작 내용 |
|---|---|
| TV — 게임 시작 | 보스 정체 공개 |
| TV — 밤 페이즈 | "밤" 안내 + 타이머(2분) |
| TV — 낮 결과 공개 | 밤 데미지 결과, 지목/심판 결과 |
| TV — 낮 토론 | 타이머(5분) |
| TV — 낮 투표 | 타이머(2분) → 투표 결과·데미지 반영 |
| 앱 — 밤 | 기본 공격/특수 능력 대상 지목 UI (역할별로 다름) |
| 앱 — 낮 투표 | 지목 투표 UI |
| 앱 — 상시 | 본인 HP, 역할, (스파이인 경우) 동료 스파이 닉네임 |
| 앱 — 사망 후 | 사망 안내 → 모든 버튼 비활성화된 관전 모드 |
| 진행자 관리 화면 | 페이즈별 타이머 강제 종료/연장 |

## 밸런스 고려사항 / 트레이드오프

* 직접 개발 방식을 택하면서 지금까지 정한 동시 지목·자동 합산·자동 공개 같은 기획을 손실 없이 구현할 수 있게 됐지만, 그만큼 개발 리소스가 필요해진다 — 실제 구현은 별도의 개발 계획(설계 스펙/구현 플랜) 단계에서 다뤄야 한다.
* 방 코드+닉네임 재접속 자동 복귀 덕분에, 파티 도중 와이파이 문제 등으로 튕겨도 게임이 깨지지 않는다. 다만 닉네임이 겹치면 다른 사람으로 오인될 위험이 있어, 방 안에서 닉네임 중복은 막아야 한다(구현 세부사항).
* 진행자를 항상 필요로 하는 대신 완전 자동 모드 개발 부담을 덜었다. 다만 진행자도 역할을 겸해야 하므로, 진행자가 자기 능력을 쓰는 타이밍에 관리 화면도 같이 조작해야 하는 부담이 있을 수 있다 — 플레이테스트로 확인 필요.
