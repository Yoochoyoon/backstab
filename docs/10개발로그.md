**실제 폰으로 처음부터 끝까지 풀 플레이 테스트** — 봇 5명 + 사용자 본인 폰(보스 역할)으로 로비 입장부터 게임 종료(스파이 승리)까지 실제 게임을 진행하며 페이즈 슬라이드 4종(밤 시작/밤 결과/토론 시작/투표 시작), 사망 연출, 보스 위급 상태(빨간 테두리) 강조를 전부 실제 플레이 중 스크린샷으로 확인. 이 과정에서 폰 화면 스크린샷을 통해 드러난 실사용 버그 여러 개를 발견해 수정함.

**재접속 시 스킬/HP바가 안 뜨던 근본 원인 수정** — `player:reconnect` 핸들러가 세션은 검증하면서도 `player.id`(과 세션의 `playerId`)를 새 소켓 id로 갱신하지 않아서, 재접속 이후엔 `io.to(player.id).emit(...)`으로 보내는 밤 행동 옵션이 끊어진 예전 id로 날아가 아예 도착하지 못하고, `room.players.find(p => p.id === socket.id)`로 찾는 밤 행동/투표 제출 핸들러도 조용히 실패하고 있었다. 재접속 시 `player.id`/`session.playerId`를 새 `socket.id`로 갱신하도록 수정 — 폰을 새로고침해도 스킬 선택과 투표/공격 제출이 계속 정상 동작한다.

**HP바 계산 버그 수정** — 플레이어 화면의 HP 바가 역할별 최대 HP(보스 5, 그 외 4) 대신 무조건 5로 나눠 계산되고 있어서 보스가 아닌 역할은 항상 실제보다 낮은 비율로 표시됐고, 재접속 직후에는 실제 HP와 무관하게 무조건 100%로 그려지고 있었다. `getMaxHpForRole()`을 써서 정확한 비율로 계산하도록 수정.

**스킬 설명 보강 및 카드 레이아웃 변경** — 기존에 "데미지 1", "쿨타임 1라운드"처럼 대충 적혀있던 6개 스킬(기본 공격/긴급 처형/육탄 방어/충성심 서약/교란 작전/흑막의 미소) 설명을 효과·제한 횟수까지 명확히 담아 다시 썼다. 설명이 길어져 기존 2열 카드에서는 짓눌리므로 `.na-skill-grid`를 1열로 변경.

**모바일 가독성/레이아웃 개선 3건**
- 페이즈 전환 슬라이드: 모바일에서 제목/설명 글씨 크기를 키우고 설명 텍스트에 검은 외곽선(text-shadow) 추가.
- 호스트 화면 결과 로그(`#resultLog`): `<br>`로 세로 나열되던 걸 `<span>` 기반 flex-wrap 가로 한 줄로 바꾸고 글씨도 키움.
- 호스트 화면(`.host-layout`)이 `height:100vh`를 쓰고 있어 모바일 브라우저 주소창 유무만큼 실제 보이는 영역보다 커지고, `overflow:hidden`과 만나 하단(`.control-lower`의 결과 로그/시간 연장/다음 단계로 버튼)이 화면 밖으로 잘려 안 보일 수 있던 문제를 `height:100dvh`(동적 뷰포트 높이)로 교체해 해결.

- 참가자 HP 모니터에서 보스 제외 — 오른쪽 보스 카드에 이미 이름/HP가 있어서 중복이었음(`02역할.md` 기준 보스가 유일한 공개 역할이라는 근거로 판단).
- HP pip 크기/텍스트 확대, 밤·토론·투표 이모지를 플랫 SVG 도형(초승달/말풍선/체크박스)으로 교체하고 검정 배경+흰 아이콘, 현재 라운드만 노란 테두리로 강조.
- 사망한 참가자 카드에 어두운 오버레이 + 30도 기울어진 큼직한 "사망" 도장 텍스트 연출.
- 밤 페이즈에서는 카드/박스의 흑백을 반전(검정↔흰색)해서 분위기를 확실히 바꾸되 노랑·빨강 강조색은 유지, 350ms 트랜지션.
- 반복 발견된 버그 패턴: `element.style.display = "block"`이 CSS `display:flex`(gap 포함)를 인라인으로 덮어써서 조용히 레이아웃을 깨는 문제가 host.js/player.js 양쪽에서 여러 번 나왔음(bossBanner, gameSection, postJoinScreen, actionSection 등) — 전부 `"flex"`로 수정.
- CSS Grid/Flex 아이템의 기본 `min-width:auto`가 내용이 트랙보다 크면 안 줄어들고 그대로 잘려나가는 문제를 발견해(모바일도 데스크탑도 아닌 640~800px대 좁은 창에서 재현) 관련 요소 전부 `min-width:0` 추가.
- 디자인 통일: 기존 화면들과 같은 테두리 두께(`0.5vh` 표준, 참가자 카드만 `0.7vh`로 강조), 사건번호/라운드는 검정 테두리+흰 면, 타이머는 흰 테두리+검정 면으로 색 반전, 캐릭터 사진 자리는 그라데이션 대신 단색 검정, skewX 스티커 스타일은 반복된 잘림 문제로 전부 되돌려서 원래의 사각형 형태로.
- 배경은 새 색을 만들지 않고 랜딩 화면부터 쓰던 `.hero-card`(회전 카드+종이질감)를 그대로 재사용하도록 구조 변경.

**플레이어 밤 행동/투표 화면 신규 구현** — Figma "Android Compact - 3" 목업 기준.
- 보스공개/내역할/타이머 3박스, 스킬 선택(기본공격+역할별 특수능력 카드, 아이콘 포함), 대상 선택 그리드, 선택 요약, 지목 확정 버튼까지 전부 새로 구현. `#gameSection`이 밤/투표 공용이라 투표 페이즈에도 자동으로 대응.
- 대상 카드는 진행상황 화면의 `hp-monitor-card` 컴포넌트를 그대로 재사용(재활용 원칙) — 사망 도장 효과용 `overflow:hidden`이 위로 튀어나오는 "보스" 배지를 잘라먹는 문제만 이 화면 한정으로 `overflow:visible`로 풀어서 해결.
- 지목 완료 시 선택한 카드 테두리가 노랑→초록으로, "지목 확정" 버튼이 "지목완료"+어두운 톤으로 바뀌고 잠긴다.
- 서버가 `publicPlayers()`에서 `role` 필드를 아예 안 보내고 있어서 `p.role === "boss"` 체크가 실제 서버 데이터로는 한 번도 참이 된 적 없던 버그(수동 테스트 데이터로만 통과됐던 것)를 발견 — 보스는 공개 역할이므로 서버에서 `role:"boss"`만 흘려보내도록 수정. 참가자 HP 모니터의 보스 제외, 대상 카드의 "보스" 배지, HP 최대치 계산이 전부 이 수정 하나로 실제로 동작하게 됨.
- 재접속(`state:full_sync`) 시 서버가 방 전체 플레이어의 역할을 필터링 없이 그대로 보내고 있던 프라이버시 버그도 같이 발견해 `publicPlayers()` + 본인 역할만 별도 필드(`myRole`/`myHp`)로 분리해서 고침. 같은 경로에 보스 배너를 아예 안 띄우는 버그도 있었음(처음부터 구현이 빠져 있었음) — 같이 추가.
- 새 방에 "입장하기"를 누르면 이전 세션(localStorage의 sessionId/roomCode)을 먼저 지우도록 수정 — 안 그러면 같은 브라우저로 새로고침할 때마다 이전(어쩌면 중단된) 방으로 자동 재접속되는 문제가 있었음. 같은 방 안에서 연결이 끊겼을 때의 재접속은 그대로 유지.
- 모바일 전용 버그 3개: 타이머가 `--:--`(대기 상태)일 때 줄바꿈되며 깨지던 것(`white-space:nowrap` 누락), "대상을 선택하세요" 섹션이 밤/투표가 아닌 페이즈에서도 제목만 계속 떠 있던 것(내용만 지우고 섹션 자체는 안 숨겼던 게 원인), 게임 종료 시 상단 타이머/라벨이 직전 페이즈 문구를 그대로 들고 있던 것(`applyPhase()`가 game_over에서 이르게 return).

**페이즈 전환 슬라이드 신규 구현** — 밤 시작/토론 시작/투표 시작/밤 결과(사망자)/투표 결과(최종 지목자)마다 호스트·참가자 화면 양쪽에 잠깐 떴다 사라지는 전체화면 오버레이. `shared.js`에 `createSlideQueue()`를 만들어 host.js/player.js가 같은 방식으로 재사용하고, 큐 방식이라 연달아 오는 이벤트(예: 밤 결과 직후 바로 다음 라운드 시작)도 겹치지 않는다. 참가자가 호스트 화면 없이 자기 화면만으로 상황을 파악할 수 있게 하는 게 목적.

**신규 프로젝트 스킬 2개**
- `화면확인`: UI에 영향 주는 파일을 수정하면 사용자가 요청하지 않아도 자동으로 브라우저 스크린샷을 찍어 보여준다. 사용자의 실시간 테스트 세션(여러 플레이어 탭)은 절대 새로고침/재사용하지 않는다는 안전 수칙 포함.
- `봇채우기`: 사용자가 직접 플레이어로 테스트하고 싶을 때 방을 만들고(또는 기존 방에) 나머지 인원을 봇(자동 접속 플레이어 탭)으로 채운다.

**`docs/design.md` 20장 추가**: 테두리 두께 표, 진행 화면 박스 색 반전 규칙, 캐릭터 사진 placeholder 규칙, `.hero-card` 재사용법, `--btn-accent` 공용 버튼 패턴을 실제 구현 기준으로 문서화.
