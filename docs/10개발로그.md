**CDP 직결 QA 하네스 + 아이패드 비율에서 방 코드가 배지 밖으로 넘치던 버그** — Playwright MCP를 쓸 수 없는 상황이라, 프로젝트에 이미 (socket.io를 통해) 들어와 있던 `ws`만으로 **헤드리스 크롬을 CDP로 직접 모는 하네스**를 만들어 QA와 스크린샷 생성을 자동화했다. 사용자의 브라우저를 건드리지 않고, 뷰포트 크기를 정확히 지정할 수 있어 결과가 매번 같다.
- **승리조건 3종(스파이·보스측·배신자) 전부 완주 확인** — 8인으로 각각 강제로 만들어 `winner` 값과 종료 페이로드의 전원 역할 공개까지 검증. **인원 6/8/10명 × 화면 4종(데스크톱 1920×1080, 아이패드 가로 1180×820·세로 820×1180, 폰 390×844)** 을 전부 돌려 잘림·가로 스크롤·텍스트 넘침을 수치로 측정했고, 콘솔 에러도 같이 수집했다.
- **찾은 버그 — 방 코드가 배지를 넘침**: `.case-badge__value`의 글자 크기를 `min(3.2cqw, 3.6vh)`로 잡아뒀는데, 가장 가까운 컨테이너가 `.host-layout`(=화면 전체 폭)이라 사실상 "화면 폭의 3.2%"로 계산되고 있었다. 정작 이 배지는 상단 줄에서 가장 좁은 `1fr` 칸이라, 화면이 세로로 길어질수록(아이패드 가로/세로) 칸 폭 대비 글자만 커져 4글자 방 코드가 배지 밖으로 삐져나왔다. **인원수와 무관하게 6/8/10인 전부에서 재현**됐다.
  - 해결: 타이머 칸이 이미 같은 이유로 자기 자신에게 `container-type: inline-size`를 걸어둔 전례가 있어 같은 방식으로 맞췄다 — 배지에 컨테이너를 세워 `cqw`가 "이 칸의 폭"을 가리키게 하고, 안쪽 여백도 `vh` 대신 `em`으로 바꿨다(글자만 줄고 여백은 그대로면 좁은 칸에서 다시 넘친다). 수정 후 전 조합 넘침 0건 재확인.
  - **이건 앞선 회차에 내가 "폰트 렌더링 착시"로 잘못 판단하고 넘겼던 것과 같은 현상이었다.** 눈으로 스크린샷만 보고 판단했던 게 오진의 원인이었고, `scrollWidth > clientWidth`로 수치를 재자 바로 드러났다. 화면 문제는 반드시 수치로 판정한다는 원칙을 지켰어야 했다.

**README 전면 재작성 + 실제 플레이 스크린샷 7장** — 기존 README는 접속 주소와 배포 방법만 있는 49줄짜리였다. 게임을 처음 보는 사람이 규칙과 재미 포인트를 알 수 있도록 다시 썼다: 역할 4종의 능력과 딜레마, 라운드 진행(밤→토론→지목→심판)과 2단계 투표를 둔 이유, 승리 판정 **순서**가 왜 중요한지(배신자 분기가 죽은 코드가 됐던 사건 포함), 폰만으로 방을 여는 법과 재접속 동작까지 담았다.
- 스크린샷은 위 CDP 하네스로 **실제 게임을 한 판 세팅해서** 찍었다 — 6명이 입장한 대기실, 투표 실시간 공개(카드 위에 투표자 프로필이 쌓인 상태), 최종 심판 수배 포스터, 승리 발표(뒤로 전원 역할 공개), 그리고 폰 화면 3종(스파이 동료 공개 / 밤 스킬 선택 + 동료 실시간 현황 / 투표). 참가자 화면 주인공이 스파이일 때 UI가 가장 풍성해서, 그 역할이 나올 때까지 방을 다시 만들도록 했다.
- 캡처 직전에 **페이즈 전환 슬라이드가 완전히 사라질 때까지 기다리는 처리**를 넣었다. 처음엔 반투명 오버레이가 덮인 채로 찍혀 색이 죽고 글자가 겹쳤다.

## 2026-08-16

**자동 QA: 8인 3판으로 승리조건 3종 전부 검증 + 화면 3종 크기 점검** — 배포판(Render)에 소켓으로 봇 8명을 붙여 한 판을 통째로 몰고 가는 하네스를 만들고, 세 가지 승리를 각각 강제로 만들어 끝까지 돌렸다.
- **스파이 승리**: 스파이 3명이 보스만 집중 공격 → 보스 사망 즉시 종료. **보스측 승리**: 보스+조직원이 위협을 하나씩 정리 → 스파이 3 + 배신자 전멸. **배신자 승리**: 보스만 남기고 나머지를 걷어내 보스와 단 둘 → 즉시 종료. 셋 다 `state:game_over`의 승자 값과 전원 역할 공개까지 정상.
- 특히 **배신자 승리는 오늘 판정 순서를 고치기 전까지 도달 자체가 불가능했던 분기**라, 배포판에서 실제로 나오는 것을 확인한 게 이번 QA의 핵심이다.
- 밤 공격 합산도 따로 확인(스파이 3명 동시 공격 → 정확히 3데미지). 처음엔 1데미지로 보였는데, 원인은 제품이 아니라 하네스가 제출 직후 곧바로 진행 명령을 보내 서버에 제출보다 먼저 도착한 것이었다(제출과 진행 사이에 텀을 넣어 해결).

**큰 화면 대응 + 긴 닉네임 잘림 수정** — 위 QA를 데스크톱(1920×1080)·아이패드(1180×820, 820×1180)·폰(390×844) 세 크기로 돌리며 잡은 화면 문제들.
- **참가자 화면이 노트북에서 통째로 늘어나던 문제**: `.na-screen`에 폭 상한이 없어 1905px까지 퍼졌다. 카드 한 장이 500px을 넘고, 상단 박스는 `auto-fit`이 13칸까지 쪼개 만들어 글자가 잘렸다. 폰 UI인 만큼 `max-width: 560px` 기둥으로 묶어 가운데 정렬했다.
- **상단 박스 칸 수가 폭에 따라 흔들리던 문제**: `auto-fit + minmax`라 폭에 따라 2~3칸으로 바뀌어, 어떤 폭에선 타이머가 칸을 넘치고 어떤 폭에선 "지훈"이 "지/훈"처럼 한 글자씩 세로로 쪼개졌다. 정보 박스는 **2열 고정**, 타이머는 그 아래 한 줄 전체로 못박아 폭과 무관하게 같은 모양이 되게 했다.
- **`.na-box__value`에 남아 있던 말줄임**: "배신자"가 "배..."로 잘렸다. 앞서 카드 이름만 고치고 상단 박스를 놓쳤던 것 — 카드와 같은 규칙(줄바꿈 + `word-break: keep-all`)으로 통일했다.
- **긴 닉네임이 두 줄이 되면 HP 조각이 잘리던 문제**: 진행자 카드 비율이 본문 높이를 고정값으로 가정하고 있어서, 아이패드 폭에서 "아주긴닉네임" 카드의 조각이 28px 잘렸다. 공간이 모자라면 **사진이 먼저 줄어들도록**(`flex: 0 1 auto`) 바꿔 내용이 잘리지 않게 했다. 사진 비율은 데스크톱에서 1.28로 유지되고, 자리가 부족할 때만 완만하게 벌어진다.

**역할명 변경: 경호원 → 조직원** — 게임 톤(느와르 조직물)에 맞춰 역할 이름을 바꿨다. 화면에 보이는 문자열(`ROLE_NAMES`, `WINNER_LABELS`, 참가자 화면 역할 표시 3곳)과 기획 문서 전체(01~10, README)를 한 번에 갱신했다. **내부 식별자 `bodyguard`는 그대로 뒀다** — `Role` 타입, `ROLE_COMPOSITIONS`, 능력 키(`bodyguard_shield`/`bodyguard_oath`), 저장된 세션까지 얽혀 있어 표시 이름만 바꾸는 게 안전하고, 코드에서 역할을 가리키는 이름은 어차피 화면에 안 나온다.

**진행자 화면 색 통일 + 보스 라벨 강조** — 상단 칸들의 색 언어를 맞추고 보스 표시를 키웠다.
- **타이머·결과 패널을 왼쪽 칸들과 같은 색으로**: 둘만 검정 면 + 흰 테두리라 상단에서 따로 놀았다. 사건번호·페이즈 칸과 같은 **흰 면 + 검정 테두리 + 검정 글자**로 통일했다. 밤 반전 규칙에도 두 요소를 같이 넣어 밤에는 나머지와 함께 검정으로 뒤집히고, 흰 면에서 안 읽히던 결과 제목은 진홍으로(밤에는 다시 노랑으로) 바꿨다.
- **보스 라벨을 노란 아웃라인 글씨로**: 작은 노란 알약 배지 + 검정 글자였던 걸, **크게 기울인 노란 글씨 + 두꺼운 검정 테두리**(8방향 text-shadow)로 바꾸고 배지 배경은 뺐다. 글자 크기 2.2vh → 5.6vh. 멀리서도 보스가 바로 읽힌다.

**타이머 전체 폭 + 진행자 화면 여백 제거** — 위 수정에 이어 레이아웃을 마저 다듬었다.
- **참가자 타이머를 한 줄 꽉 채우게**: 줄바꿈으로 내려온 타이머가 반쪽만 차지해 옆이 비어 보였다. `grid-column: 1 / -1`로 한 줄을 다 쓰게 하고, 폭이 넉넉해진 만큼 글자도 26px → 37px로 키웠다.
- **보스 모니터 오른쪽 여백을 참가자 모니터에 넘김**: `.tv-upper`의 오른쪽 열이 `auto`라 결과 패널의 max-content가 열을 666px까지 넓혔는데, 보스 카드는 `min(38cqw, 460px)` 고정이라 그 오른쪽에 200px쯤 빈 공간이 남았다. 열을 보스 카드 폭으로 못박고(`1fr min(38cqw, 460px)`) 보스 카드는 열을 꽉 채우게 해서, 남던 206px이 참가자 HP 모니터로 넘어갔다(카드 폭 205px → 244px). 화면이 좌우 끝까지 채워진다.
- 결과 패널이 좁아지면서 한글이 "없었습니 / 다."처럼 어절 중간에서 잘려, `word-break: keep-all`을 걸어 어절 단위로 줄이 바뀌게 했다.

**화면 잘림·삐져나옴 3건 수정** — 실플레이 스크린샷 제보로 잡았다.
- **토론 중 프로필 사진이 가로 띠로 잘리던 문제**: 읽기 전용 목록에서 카드 높이를 아끼려고 아바타를 납작하게(`aspect-ratio: auto; height: 4.4vh`) 눌러놨는데, `object-fit: cover`와 만나 정사각형 사진이 눈코입만 남는 띠로 잘렸다. 토론 중에 얼굴로 사람을 알아보는 게 이 목록의 핵심이라, 정사각형 비율을 지키고 넘치는 높이는 페이지 스크롤로 넘겼다.
- **참가자 화면 타이머가 칸을 뚫고 나가던 문제**: 보스가 공개되면 상단이 2칸에서 3칸으로 늘어나는데, 폰 폭에서 3등분하면 한 칸이 100px도 안 돼 "01:43"이 칸 밖으로 삐져나왔다. `.na-topline`을 `minmax(min(100%, 9rem), 1fr)`로 바꿔 칸이 좁아지면 줄을 바꾸게 하고, 안전망으로 `.na-box`에 컨테이너 쿼리를 걸어 글자 크기 상한(`20cqw`)을 뒀다.
- **진행자 화면 타이머가 두 줄로 접히던 문제**: 가운데 페이즈 칸이 남는 공간을 많이 갖고 있어 타이머 칸이 `--:--`조차 담지 못했다(텍스트 315px vs 칸 310px). `.top-line` 비율을 `1fr 3fr 2fr` → `1fr 2.6fr 2.4fr`로 바꾸고 `white-space: nowrap`을 걸었다.

**배신자가 절대 이길 수 없던 문제 — 승리 판정 순서 수정** — "다른 승리 판정 없을까?"라는 질문에서 출발해 확인해보니, `checkWinner()`의 배신자 승리 분기가 **어떤 입력으로도 실행되지 않는 죽은 코드**였다. 보스 사망 판정(`if (!boss.alive) return "spy"`)이 맨 앞에 있는데 배신자가 최후의 1인이 되려면 보스가 이미 죽어 있어야 해서, 배신자 분기까지 도달할 방법이 없었다. `ROLE_COMPOSITIONS`상 배신자는 6~10인 모든 구성에 항상 1명 있으므로 **매 게임 한 명은 이길 수 없는 역할을 배정받고 있었다.** 기존 테스트는 이름이 `"lone surviving traitor wins"`인데 실제로는 `"spy"`를 단언해, 버그를 고치는 대신 버그에 맞춰 단언을 바꿔놓은 상태였다.
- **승리 조건 자체를 바꿨다**: "최후의 1인으로 혼자 생존"은 달성이 지나치게 어려웠는데, **"보스와 단 둘만 남으면 즉시 승리"** 로 변경했다. 배신자는 스파이로부터 보스를 지키면서 조직원·스파이를 걷어내는 줄타기를 하게 돼 역할의 성격도 더 살아난다.
- 판정 순서를 **① 보스·배신자 단 둘 생존 → 배신자 승 ② 보스 사망 → 스파이 승 ③ 보스 생존 + 위협 전멸 → 보스측 승** 으로 정리했다. 배신자 조건이 "보스 생존"을 전제하므로 보스가 죽는 순간 판정이 스파이 승리로 딱 떨어져 **승자가 안 나오는 교착이 원천적으로 사라진다**(무승부·라운드 상한을 두지 않기로 한 기존 결정을 그대로 지킬 수 있다).
- 잘못된 테스트를 바로잡고 경계 케이스 4개를 추가(총 47개 통과). `docs/02역할.md`의 보스·조직원·배신자 승리 조건과 `03라운드진행.md`의 종료 규칙도 새 판정에 맞게 갱신했다.

**한 명을 지목했는데 두 명이 선택되던 버그 — 같은 소켓의 중복 입장** — "클릭하면 두 명씩 선택되고 호스트 화면에서도 투표가 두 명에게 들어간다"는 제보로 잡았다. 화면 문제가 아니라 **플레이어가 중복 등록되는 서버 버그**였다.
- 원인: `player:join_room`이 같은 소켓의 재입장을 막지 않았다. 닉네임 중복 검사는 있었지만 **닉네임이 다르면 통과**하므로, 같은 소켓이 다른 이름으로 다시 입장하면 `socket.id`가 동일한 Player가 두 개 생겼다. `id`는 이 게임 전체의 플레이어 식별자라서 중복되는 순간 전부 어긋난다 — 한 명을 지목해도 `p.id === selectedTargetId`가 두 카드에 걸려 둘 다 선택된 것처럼 보이고, `voterChipsHtml`도 같은 id의 두 카드에 투표자를 찍고, 집계도 같은 표를 두 번 센다.
- 해결: `addPlayer()`가 이미 그 소켓이 자리를 잡고 있으면 `false`를 돌려주고, 핸들러가 "이미 이 방에 입장해 있습니다."로 안내한다. 한 소켓 = 한 자리 불변식을 함수 안에 못박아 모든 호출 지점이 같이 보호되게 했다. 회귀 테스트 2개 추가(총 43개), 실제 소켓으로 3번 연속 입장 시도 → 1명만 등록되는 것까지 확인.
- 같이 발견한 표시 문제: `.is-me`(내 카드)와 `.selected`(내가 지목한 카드)가 똑같은 노란 실선이라 읽기 전용 목록에서 둘을 구분할 수 없었다. 내 카드는 흰색 점선으로 바꿔 역할을 갈랐다.

**진행자 화면 UI 버그 6건 수정 + 게임 나가기 버튼 추가** — 실플레이 QA 중 발견한 자잘한 화면 버그 모음.
- **찬반 심판 포스터의 원형 프로필 사진이 찌그러져 보이던 문제**: 포스터 자체가 팝아트 연출로 `skewX(-8deg)` 기울어 있는데, 그 안에 넣은 투표자 원형 사진도 그대로 기울어 타원처럼 보였다. 사진(`.voter-chip`)에만 반대 방향(`skewX(8deg)`)을 걸어 상쇄해 포스터는 그대로 기울어 있어도 사진은 똑바로 보이게 했다.
- **참가자 HP 모니터 카드가 화면 비율에 따라 과도하게 높아지던 문제**: 아바타가 `aspect-ratio: 1/1`로 카드 너비를 그대로 따라가는데, 카드가 낮고 넓은 화면(가로로 넓은 TV 등)에서는 아바타 높이가 카드 전체 높이를 넘어서 이름·HP가 `overflow:hidden`에 통째로 잘렸다. `max-height: 50%` 상한을 걸어 해결. 단, 모바일 지목 카드(`.na-target-grid`, 높이가 콘텐츠에 맞춰 자동으로 늘어나 애초에 문제가 없던 화면)에는 이 상한이 오히려 정사각형을 찌그러뜨려서 별도로 상한을 해제했다.
- **시간 연장 시 페이즈 전환 슬라이드가 다시 뜨던 문제**: "시간 연장" 버튼은 서버가 `state:phase_changed`를 같은 페이즈로 재전송하는데, 클라이언트가 페이즈 값이 실제로 바뀌었는지 확인하지 않고 무조건 슬라이드를 띄웠다. 직전 페이즈를 기억해뒀다가 실제로 바뀐 경우에만 슬라이드를 띄우도록 수정(호스트·플레이어 화면 둘 다).
- **밤 배경을 빨강 대신 파랑으로**: 낮/밤 구분이 카드 색 반전 정도로만 있었는데, 배경 자체도 밤 전용 파란 그라디언트(`--hero-night-blue-gradient`)로 바꿔 분위기를 더 확실히 갈랐다.
- **라운드 진행 아이콘의 "현재 단계" 강조를 검정 배경+노란 아이콘에서 노란 배경+검정 아이콘으로 변경**. 밤 페이즈의 흑백 반전 규칙이 이 강조 스타일을 덮어써서 밤에는 어느 아이콘이 활성 상태인지 안 보이던 부수 버그도 같이 발견해 수정(밤 전용으로 노란 강조를 다시 못박음).
- **게임 나가기 버튼 추가**: 호스트·플레이어 화면 어디서나 우측 상단 고정 위치에서 나갈 수 있게 했다. 입장 화면(아직 방에 안 들어간 상태)에는 숨겨서 타이틀과 안 겹치게 하고, 방에 들어간 뒤에는 항상 노출. 서버 쪽은 기존 재접속/유예 로직을 그대로 재사용 — 로비에서는 곧 제거되고, 게임 중에는 재접속 대기 상태로 남는다(진행자가 나가도 타이머 기반 자동 진행은 계속된다).

**실플레이 피드백 6건 반영 — 정보를 감추지 말고 다 보여주기** — 배포판에서 직접 스파이로 뛰어본 뒤 나온 개선 요청 6개를 한 번에 처리했다. 공통된 문제의식은 "지금 뭐가 일어나고 있는지 각자 화면에서 안 보인다"였다.
- **닉네임 말줄임 제거**: 참가자 카드 이름이 한 줄 말줄임이라 조금만 길어도 뒤가 잘렸다. 이름과 역할은 이 카드에서 제일 중요한 정보라 줄바꿈을 허용하도록 바꿨다.
- **`day_reveal`(결과공개) 페이즈 삭제**: 진행자가 버튼을 눌러야만 넘어가는 단계라 온라인에선 흐름만 끊었다. 밤이 끝나면 `resolveNight()`이 곧바로 토론을 연다. 결과는 슬라이드와 상시 결과 패널로 이미 전달되므로 전용 화면이 없어도 정보 손실이 없다.
- **패널 중복 정리**: 참가자 명단 패널이 둘(지목용 `#targetList` + 읽기 전용 로스터)이라 같은 걸 두 번 봤다. 로스터를 없애고 `renderTargetList()` 하나가 겸하게 했다 — 지목/투표 중엔 선택 가능, 그 외 페이즈(토론 포함)엔 읽기 전용으로 계속 떠 있다. 진행자 화면에서는 보스 모니터 높이를 줄이고 그 위에 결과 패널(`.result-panel`)을 사건번호 칸보다 큰 글자로 올렸다.
- **입장 전 프로필 사진 등록**: 입장 화면에서 사진을 고르면 클라이언트가 캔버스로 128px 정사각형 JPEG로 줄여 보낸다(서버는 `data:image/` 접두사 + 40KB 상한만 통과). 카드 사진 자리가 채워져 누가 누군지 한눈에 들어온다.
- **동료 스파이 현황 실시간화**: 밤 채팅을 넣는 대신 기존 `spy:teammate_preview`를 확장했다. 동료가 아직 고르는 중이면 `(고르는 중)`, 제출까지 마쳤으면 `(확정)`으로 갈라 보여준다 — 확정 표시를 믿어야 같은 대상에 합공을 몰아칠 수 있어서, 자유 채팅 없이도 밤 협업이 성립한다.
- **투표 실시간 공개**: 지목 투표와 찬반 심판 **둘 다** 누가 누구를 찍고 있는지 공개한다. 지목 투표는 각 카드 사진 위에 투표자 프로필을 작은 원으로 겹쳐 얹고(`voterChipsHtml`), 찬반 심판은 수배 포스터 아래에 찬성/반대 진영을 갈라 프로필로 늘어놓는다(`judgementTallyHtml`). 서버는 `emitSubmissionProgress`에서 `state:vote_progress`를 같이 쏘고, 진행자·참가자 화면이 같은 헬퍼로 그린다.

**`/자동QA` 스킬로 배포판 무인 회귀 실행 — 실제로 3건의 제품 버그를 새로 찾아 고침** — 소켓 봇 하네스(한 페이지에서 `io()`를 여러 개 열어 방을 통째로 모는 방식)를 배포판(Render)에 붙여 승리조건 3종(스파이/보스측/배신자)을 각각 강제로 완주시키고, 6·7·10인 진행자 화면과 참가자 화면(실제 UI로 입장, 라 스포일러 없이 봇으로 채움)을 데스크톱·아이패드·폰 세 크기에서 훑었다. 화면 쪽은 전부 정상이었지만(잘림·가로스크롤 0건), 이 과정에서 로직 버그 3건이 실제로 걸렸다 — 전부 유닛 테스트로는 잡을 수 없고 실시간 소켓 흐름을 태워야만 드러나는 종류였다.
- **방장이 "다음 단계로"를 누르면 그 페이즈의 자연 타이머가 안 지워지던 문제**: `host:advance_phase`가 `resolveVote()` 등을 직접 불러 수동으로 페이즈를 넘기면서도 `scheduleTimedPhase`가 걸어둔 `room.phaseTimer`(자연 만료 시 자동으로 같은 함수를 부르는 `setTimeout`)를 지우지 않았다. 그 타이머는 버려진 채 계속 카운트다운하다가, 원래 예정됐던 시각에 이미 몇 라운드나 지난 방 상태를 대고 `resolveVote()`를 한 번 더 불렀다 — 투표/밤 처리가 조용히 중복 실행되며 진행이 알 수 없게 꼬였다(실제로 QA 중 `day_vote`가 영원히 안 넘어가는 것처럼 보이는 현상으로 걸렸다). "다음 단계로"는 타이머보다 먼저 눌리는 게 정상적인 사용 방식이라 **사실상 그 버튼을 쓸 때마다 매번 새고 있었다**. `host:advance_phase` 맨 앞에 `clearPhaseTimer(room)`을 추가해 고쳤다.
- **게임 종료 시 참가자 최종 결과 화면이 항상 조용히 안 뜨던 크래시**: `player.js`의 `applyPhase()`에서 `game_over` 분기가 `instructionLabel`/`submitBtn`/`summaryPanel`을 참조하는데, 그 세 `const` 선언이 함수 뒤쪽(day_vote 슬라이드 분기 다음)에 있어서 **게임이 끝날 때마다 "Cannot access before initialization" 예외로 함수가 그 자리에서 멈췄다.** 그 뒤에 있던 `overSection` 표시, 역할 공개 문구, 최종 결과 카드 렌더링이 전부 실행되지 못했는데, 마침 그 위를 승리 슬라이드가 덮고 있어서 화면상으로는 안 드러났다 — 슬라이드를 닫으면 참가자는 마지막 라운드 화면 그대로 남아 **최종 결과를 한 번도 볼 수 없었다.** 세 선언을 함수 앞쪽으로 옮겨 game_over 분기보다 먼저 초기화되게 했다.
- **뒤늦게 도착한 자동 재접속 응답이 방금 새로 만든/입장한 방을 조용히 덮어쓰던 문제**: 페이지가 뜨면 `server:hello`를 받는 즉시 저장된 세션으로 `player:reconnect`를 자동 시도하는데, 그 응답이 오기 전에 사용자가 "입장하기"나 "이름만 적고 새 방 만들기"를 누르면 두 흐름이 경쟁했다. `clearSession()`은 앞으로 저장될 세션만 막을 뿐 이미 날아간 재접속 요청은 취소하지 못해, 나중에 도착하는 쪽이 이겼다 — 재접속이 늦게 이기면 방금 만든 방 코드가 안 뜨거나 방장 버튼이 없는 채로 남았다. 클릭 시점에 `startedNewSession` 플래그를 바로 세워 그 이후 도착하는 재접속 응답을 전부 무시하게 했다. 실제 스테일 세션 + 0ms 지연으로 경쟁시켜 재현 후 고침을 확인했다.
- 세 건 다 배포판에 반영 후 같은 시나리오로 재현 테스트를 다시 돌려 더 이상 발생하지 않는 것까지 확인했다. 셋 다 **하네스가 아니라 실제 제품 코드의 버그**였다 — 하네스 쪽 문제(제출과 진행 사이 텀 부족 등)는 이번 라운드에서는 없었다.

**낮 투표를 2단계로 — 지목 투표 + 찬반 심판** — 지목이 곧 처형이라 낮이 단순 다수결로 끝나던 것을, "누구를 심판대에 세울지"(지목 투표)와 "실제로 칠지"(찬반 심판) 두 단계로 나눴다. 지목만으로는 피해가 없고, 지목된 사람을 진행자 화면 한가운데와 각자 폰에 **수배 포스터처럼 크게 띄운 채** 찬반을 받아 가결돼야 데미지 1이 들어간다. 원래 논의하던 보스 "지명 수배"(단순 표시)를 대신하는 기능이면서, 지목된 사람의 변론이 한 번 더 들어가 토론이 살아난다.
- **밸런스 결정**: 가결 효과는 기존 낮 투표 데미지 1을 그대로 유지(03라운드진행.md의 "밤 공격이 더 무거운 수단" 원칙 보존). 찬성 > 반대여야 가결이고 동수·기권은 부결. 대상자 본인도 투표 가능.
- `resolveDayVote`를 집계만 하는 `tallyDayVote`와 심판을 처리하는 `resolveJudgement`로 분리하고 유닛 테스트 8개를 붙였다(총 35개).
- 심판 단계에도 채팅을 열어뒀다 — 변론할 수 없으면 이 단계를 넣은 의미가 없다.

**투표 결과가 "??? 최종 지목"으로 뜨던 버그** — 스파이로 플레이한 QA 판에서 발견. `state:vote_result`는 `topTargetId`만 보내고 클라이언트가 id로 닉네임을 찾게 했는데, 지목당한 사람이 방금 재접속해 소켓 id가 바뀌었으면 조회에 실패해 "???"가 떴다. 서버가 `topTargetNickname`을 같이 보내고 클라이언트는 그걸 우선 쓰도록 수정(심판 이벤트는 원래 닉네임을 같이 보내고 있어서 포스터는 멀쩡했다).

**배포판 8인 실플레이 QA에서 잡은 버그 3종** — 봇 7 + 실제 폰 1명으로 배포판에서 4라운드 완주(스파이 승리)하며 발견.
- **재접속하면 이미 제출한 밤 행동·투표가 조용히 사라지던 버그**: `room.nightActions`/`dayVotes`/`judgementVotes`가 전부 **소켓 id를 키로** 쓰는데, 재접속 시 `player.id`만 새 소켓 id로 갈아끼우고 이 키들은 그대로 뒀다. 그래서 제출한 뒤 재접속하면 그 제출이 주인 없는 키로 남아 버려졌다(3라운드 밤에 봇3의 공격이 실제로 유실됨).
- **심판이 가결됐는데 아무도 안 다치던 버그**: 같은 원인. `room.judgementTargetId`도 소켓 id라, 지목된 사람이 재접속하면 대상 id가 어긋나 `resolveJudgement`가 대상을 못 찾고 데미지를 건너뛰었다. 실제로 찬성 5·반대 2로 가결됐는데 HP가 그대로였다.
  - 두 버그 모두 `remapPlayerId()`로 해결 — 재접속 시 소켓 id를 식별자로 쓰는 방 상태(제출 키, 지목 대상, 동점자 목록, 마지막 투표 결과)를 전부 새 id로 옮긴다. 유닛 테스트 6개 추가(총 41개).
- **진행자 화면 타이머가 게임 종료 후에도 계속 돌던 버그**: `timerLabel.textContent`만 비우고 `startCountdown`의 인터벌은 안 껐다. 인터벌이 250ms마다 다시 써넣어 "게임 종료"인데 숫자가 줄어들었다.
- **종료 화면에서 역할이 잘려 안 보이던 문제**: 참가자 카드 이름이 한 줄 말줄임이라 "봇3 (스파..."로 잘렸다. 역할 공개가 이 화면의 결론인데 정작 그게 안 보였다. 종료 시에는 줄바꿈을 허용하고, 이름을 덮던 큰 "사망" 도장도 뺐다.

**폰에서만 밤 스킬 목록이 안 보이던 버그 수정** — "데스크톱 창을 모바일 폭으로 줄이면 보이는데 진짜 폰에서는 안 보인다"는 제보로 잡은 버그. CSS 문제가 아니라 **재접속 시 비공개 정보가 복원되지 않는 문제**였다. `player:night_options`(밤 스킬 목록)와 `player:spy_reveal`(동료 스파이 명단)은 페이즈 시작 때 해당 플레이어에게 딱 한 번만 보내는데, `player:reconnect`는 `state:full_sync`만 보내고 이 둘을 다시 보내지 않았다. 그래서 폰이 탭을 버렸다 다시 열면(모바일 브라우저의 흔한 탭 폐기) 클라이언트의 `myNightOptions`가 기본값 `{specialActions: []}`으로 시작하고, `renderActionChoices()`가 `actions.length <= 1`이면 섹션을 통째로 숨기는 로직 때문에 스킬 영역이 사라졌다. 데스크톱에서는 탭이 안 버려지니 재현되지 않았다.
- `emitPrivateStateTo()`를 추가해 재접속 시 밤 스킬 목록과 스파이 동료 명단을 다시 보내도록 수정.
- 순수 소켓 시나리오로 검증: 스파이 소켓을 끊고 **완전히 새 소켓 + 저장된 세션**으로만 복귀시켜 두 정보가 모두 복원되는 것을 확인. 페이지 새로고침 경로도 별도로 확인.

**찬반 심판 연출 다듬기 (진행자 요청)** — 심판 포스터가 HP 카드 위에 그냥 얹혀서 뭘 가린 건지 애매해 보인다는 피드백을 받아, 심판 중에는 무대(위쪽)를 반투명 검정(`rgba(0,0,0,0.72)`)으로 눌러 포스터만 도드라지게 했다. 진행자 조작 바("시간 연장"/"다음 단계로")는 어둡게 덮지 않고 그 위로 올려 비활성처럼 보이지 않게 함. 이후 포스터를 더 키워달라는 요청에 이름 글자를 `min(20vh, 17cqw)`까지 키우되, 최대 길이(7자) 닉네임이 3줄로 접혀 화면을 다 먹는 걸 막기 위해 글자 수(`--name-len`)에 맞춰 폰트가 자동으로 줄어들도록 `calc()`를 걸고 한 줄 고정(`white-space: nowrap`)으로 바꿨다 — 짧은 이름은 최대 크기로, 긴 이름은 가로로 늘어나며 항상 한 줄에 담긴다.
- 구현 중 `.tv-upper`가 `z-index:4 + position:relative`로 별도 쌓임 맥락을 만들고 있어서 포스터(`z-index:6`)가 그 안에서 배경 위로 못 올라오던 문제를 발견 — 포스터를 `.host-layout`의 직계 자식으로 옮겨 해결.

**온라인 플레이 지원 2단계 — 안정성**
- **방/세션 자동 청소**: 방과 세션이 메모리 `Map`에만 있는데 만료 로직이 아예 없어서, 끝난 게임과 버려진 방이 프로세스가 죽을 때까지 계속 쌓이기만 했다(느린 메모리 누수). `Room.lastActivityAt`을 추가하고 10분마다 정리한다 — 끝난 방은 30분, 진행 중인데 아무도 안 돌아오는 방은 6시간 뒤. 판정 로직은 순수 함수(`isRoomExpired`/`cleanupExpiredRooms`)로 뽑아 유닛 테스트 6개를 붙였다.
- **서버 재시작을 조용한 실패에서 명확한 안내로**: 재시작되면 재접속이 "세션을 찾을 수 없습니다"로 실패하는데 사용자는 이유를 알 수 없었다. `server:hello`로 서버 부팅 시각을 내려보내고, 저장된 세션이 그보다 오래됐을 때만 "서버가 재시작되어 이전 게임이 종료되었습니다"라고 안내하고 세션을 정리한다(일시적 실패로는 지우지 않는다).
- **로비에서 끊기면 방이 통째로 사라지던 문제**: 로비 이탈은 즉시 제거였기 때문에, 방을 만든 사람이 폰 화면을 한 번 껐다 켜는 것만으로 (혼자였다면) 방이 삭제되고 이미 나눠준 방 코드가 무효가 됐다. 방장 모드에선 치명적이라 1분 유예를 두고, 로비 상태에서도 재접속을 허용하도록 고쳤다(대기실 화면·방 코드·시작 버튼까지 복원).
- **탭마다 세션이 섞이던 문제**: 세션을 `localStorage`에만 저장해서 같은 브라우저의 여러 탭이 서로의 세션을 덮어썼다. 나중에 들어온 탭이 앞 탭의 세션을 지우는 바람에, 새로고침하면 **남의 플레이어로 재접속**되는 일이 생겼다(실기기 여러 대로 하는 실제 플레이엔 영향 없지만, 봇 탭 QA는 계속 깨졌다). 탭 전용 `sessionStorage`를 우선 저장소로 쓰고 `localStorage`는 브라우저를 완전히 닫았다 연 경우의 보조로 두도록 바꿨다.

**온라인 작업 중 발견해 같이 고친 버그 3종**
- **재투표 시 제출 배지가 안 뜨던 문제**: `state:vote_result`가 넣어준 동점자 제한(`voteAllowedTargetIds`)을 곧바로 이어지는 `day_vote` 진입 처리가 매번 `null`로 덮어써서, 재투표인데 아무나 찍을 수 있게 보이고 서버는 그 표를 조용히 버렸다. 초기화 시점을 `day_discussion` 진입으로 옮겨 해결(재투표는 토론을 건너뛰므로).
- **재접속 시 같은 문제**: `state:full_sync`가 `voteAllowedTargetIds`를 보내주는데도 클라이언트가 읽지 않고 있었다.
- **채팅 전송 버튼이 입력창을 25px로 찌그러뜨리던 레이아웃 버그**: 전역 `button { width: 100% }` 규칙이 `flex: none`을 이겨서 버튼이 줄 전체를 차지했다. `width: auto`로 되돌려 해결.

**실제 폰으로 처음부터 끝까지 풀 플레이 테스트** — 봇 5명 + 사용자 본인 폰(보스 역할)으로 로비 입장부터 게임 종료(스파이 승리)까지 실제 게임을 진행하며 페이즈 슬라이드 4종(밤 시작/밤 결과/토론 시작/투표 시작), 사망 연출, 보스 위급 상태(빨간 테두리) 강조를 전부 실제 플레이 중 스크린샷으로 확인. 이 과정에서 폰 화면 스크린샷을 통해 드러난 실사용 버그 여러 개를 발견해 수정함.

**재접속 시 스킬/HP바가 안 뜨던 근본 원인 수정** — `player:reconnect` 핸들러가 세션은 검증하면서도 `player.id`(과 세션의 `playerId`)를 새 소켓 id로 갱신하지 않아서, 재접속 이후엔 `io.to(player.id).emit(...)`으로 보내는 밤 행동 옵션이 끊어진 예전 id로 날아가 아예 도착하지 못하고, `room.players.find(p => p.id === socket.id)`로 찾는 밤 행동/투표 제출 핸들러도 조용히 실패하고 있었다. 재접속 시 `player.id`/`session.playerId`를 새 `socket.id`로 갱신하도록 수정 — 폰을 새로고침해도 스킬 선택과 투표/공격 제출이 계속 정상 동작한다.

**HP바 계산 버그 수정** — 플레이어 화면의 HP 바가 역할별 최대 HP(보스 5, 그 외 4) 대신 무조건 5로 나눠 계산되고 있어서 보스가 아닌 역할은 항상 실제보다 낮은 비율로 표시됐고, 재접속 직후에는 실제 HP와 무관하게 무조건 100%로 그려지고 있었다. `getMaxHpForRole()`을 써서 정확한 비율로 계산하도록 수정.

**스킬 설명 보강 및 카드 레이아웃 변경** — 기존에 "데미지 1", "쿨타임 1라운드"처럼 대충 적혀있던 6개 스킬(기본 공격/긴급 처형/육탄 방어/충성심 서약/교란 작전/흑막의 미소) 설명을 효과·제한 횟수까지 명확히 담아 다시 썼다. 설명이 길어져 기존 2열 카드에서는 짓눌리므로 `.na-skill-grid`를 1열로 변경.

**모바일 가독성/레이아웃 개선 3건**
- 페이즈 전환 슬라이드: 모바일에서 제목/설명 글씨 크기를 키우고 설명 텍스트에 검은 외곽선(text-shadow) 추가.
- 호스트 화면 결과 로그(`#resultLog`): `<br>`로 세로 나열되던 걸 `<span>` 기반 flex-wrap 가로 한 줄로 바꾸고 글씨도 키움.
- 호스트 화면(`.host-layout`)이 `height:100vh`를 쓰고 있어 모바일 브라우저 주소창 유무만큼 실제 보이는 영역보다 커지고, `overflow:hidden`과 만나 하단(`.control-lower`의 결과 로그/시간 연장/다음 단계로 버튼)이 화면 밖으로 잘려 안 보일 수 있던 문제를 `height:100dvh`(동적 뷰포트 높이)로 교체해 해결.

- 밤 페이즈에서는 카드/박스의 흑백을 반전(검정↔흰색)해서 분위기를 확실히 바꾸되 노랑·빨강 강조색은 유지, 350ms 트랜지션.
- 반복 발견된 버그 패턴: `element.style.display = "block"`이 CSS `display:flex`(gap 포함)를 인라인으로 덮어써서 조용히 레이아웃을 깨는 문제가 host.js/player.js 양쪽에서 여러 번 나왔음(bossBanner, gameSection, postJoinScreen, actionSection 등) — 전부 `"flex"`로 수정.
- CSS Grid/Flex 아이템의 기본 `min-width:auto`가 내용이 트랙보다 크면 안 줄어들고 그대로 잘려나가는 문제를 발견해(모바일도 데스크탑도 아닌 640~800px대 좁은 창에서 재현) 관련 요소 전부 `min-width:0` 추가.

- 재접속(`state:full_sync`) 시 서버가 방 전체 플레이어의 역할을 필터링 없이 그대로 보내고 있던 프라이버시 버그도 같이 발견해 `publicPlayers()` + 본인 역할만 별도 필드(`myRole`/`myHp`)로 분리해서 고침. 같은 경로에 보스 배너를 아예 안 띄우는 버그도 있었음(처음부터 구현이 빠져 있었음) — 같이 추가.
- 새 방에 "입장하기"를 누르면 이전 세션(localStorage의 sessionId/roomCode)을 먼저 지우도록 수정 — 안 그러면 같은 브라우저로 새로고침할 때마다 이전(어쩌면 중단된) 방으로 자동 재접속되는 문제가 있었음. 같은 방 안에서 연결이 끊겼을 때의 재접속은 그대로 유지.
- 모바일 전용 버그 3개: 타이머가 `--:--`(대기 상태)일 때 줄바꿈되며 깨지던 것(`white-space:nowrap` 누락), "대상을 선택하세요" 섹션이 밤/투표가 아닌 페이즈에서도 제목만 계속 떠 있던 것(내용만 지우고 섹션 자체는 안 숨겼던 게 원인), 게임 종료 시 상단 타이머/라벨이 직전 페이즈 문구를 그대로 들고 있던 것(`applyPhase()`가 game_over에서 이르게 return).

**페이즈 전환 슬라이드 신규 구현** — 밤 시작/토론 시작/투표 시작/밤 결과(사망자)/투표 결과(최종 지목자)마다 호스트·참가자 화면 양쪽에 잠깐 떴다 사라지는 전체화면 오버레이. `shared.js`에 `createSlideQueue()`를 만들어 host.js/player.js가 같은 방식으로 재사용하고, 큐 방식이라 연달아 오는 이벤트(예: 밤 결과 직후 바로 다음 라운드 시작)도 겹치지 않는다. 참가자가 호스트 화면 없이 자기 화면만으로 상황을 파악할 수 있게 하는 게 목적.

**신규 프로젝트 스킬 2개**
- `화면확인`: UI에 영향 주는 파일을 수정하면 사용자가 요청하지 않아도 자동으로 브라우저 스크린샷을 찍어 보여준다. 사용자의 실시간 테스트 세션(여러 플레이어 탭)은 절대 새로고침/재사용하지 않는다는 안전 수칙 포함.
- `봇채우기`: 사용자가 직접 플레이어로 테스트하고 싶을 때 방을 만들고(또는 기존 방에) 나머지 인원을 봇(자동 접속 플레이어 탭)으로 채운다.

**`docs/design.md` 20장 추가**: 테두리 두께 표, 진행 화면 박스 색 반전 규칙, 캐릭터 사진 placeholder 규칙, `.hero-card` 재사용법, `--btn-accent` 공용 버튼 패턴을 실제 구현 기준으로 문서화.
